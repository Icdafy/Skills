# 行业分析固定目录模板

本文件是 `hangye-fenxi-pro` 的结构总纲。它服务于立项报告中的“二、所属行业分析”章节，不是完整行业研究报告模板。

## 一、固定标题体系

成稿必须从以下标题开始，不得在前面增加“XX行业分析”“行业定义与研究边界”等大标题：

```markdown
二、所属行业分析

（一）行业发展现状

1.市场规模与增长趋势

2.核心增长驱动力

（二）产业链分析

1.产业链概况

2.产业链洞察与启示
```

可在三级标题下继续使用：

```markdown
（1）政策驱动
（2）市场驱动
（3）技术驱动/成本驱动/供给驱动/国产替代驱动（按需）
```

产业链概况下固定使用：

```markdown
（1）产业链上游
（2）产业链中游
（3）产业链下游
```

标题层级固定为：`二、` → `（一）` → `1.` → `（1）` → 段内“一是/二是/三是”。除非用户要求，不新增“竞争格局分析、行业风险分析、行业投资判断小结”等同级章节；相关判断可压缩进产业链洞察或正文尾句。

## 二、范文结构路径选择

两篇范文说明，“行业发展现状”下的三级标题不是机械唯一，而是要服务标的所处赛道。先判断行业口径，再选择路径。

### 路径 A：市场规模先行型

适用于行业已有明确市场规模口径，且标的所在细分市场可以与总市场对比的项目。默认结构为：

```markdown
（一）行业发展现状

1.市场规模与增长趋势

2.核心增长驱动力
```

写作逻辑：先用总量和细分数据证明行业高增长，再解释增长由政策、市场、技术/成本等因素驱动。该路径适合工业无人机、机器人、检测服务、能源运维、工业软件等市场统计较成熟的行业。

### 路径 B：关键配套/基础设施先行型

适用于标的是更窄的技术环节、核心终端、关键零部件、系统模块或基础设施配套，广义行业规模不能直接解释标的需求的项目。默认结构为：

```markdown
（一）行业发展现状

1.XX 是 XX 场景规模化发展的核心基础设施/关键配套

2.市场规模与增长趋势
```

写作逻辑：先证明该细分环节为什么成为下游场景的刚性配套，再写市场规模和增长趋势。第一节可按 `（1）政策支持层面`、`（2）市场需求层面` 或 `（1）政策驱动`、`（2）需求驱动` 展开。

不要把路径 B 写成技术科普。必须回答“没有该环节，下游场景为什么无法规模化；政策、客户需求和技术路线如何共同把它变成刚需”。

## 三、内部研究边界

不要输出“行业定义与研究边界”标题，但动笔前必须完成边界判断：

| 问题 | 写作用途 |
|---|---|
| 标的狭义赛道是什么 | 决定市场规模和产业链口径 |
| 标的广义行业是什么 | 决定政策和宏观背景口径 |
| 标的产品/服务卖给谁 | 决定市场驱动和下游场景 |
| 标的处于上游/中游/下游哪一环 | 决定产业链概况与启示落点 |
| 标的是否跨多个环节 | 决定是否写“一体化卡位”及主要壁垒 |

边界判断只在正文中自然体现，例如“标的公司主要处于中游系统集成与下游行业解决方案环节”，不要单独设节。

## 四、（一）行业发展现状

本部分回答“行业是否处于值得关注的增长阶段，以及增长由什么驱动”。开头可用一段加粗总起句概括行业阶段和投资含义，但不要写成独立小标题。

### 路径 A：1.市场规模与增长趋势

**核心结论前置**：首段必须加粗，压缩回答“行业规模多大、增长多快、标的所在细分是否跑赢总体、未来趋势是什么”。

推荐结构：

1. 行业总规模：近 3-5 年市场规模、CAGR、当前规模；
2. 细分市场：与标的直接相关的细分赛道规模、增速、占比；
3. 增长趋势：从历史增长写到未来 3-5 年趋势，区分历史事实与预测；
4. 结构判断：说明增长来自总体扩张、细分渗透率提升、价格上升、装机/客户数增加，还是产品升级；
5. 阶段判断：导入期、成长期、成熟期、分化期，给出理由。

成熟写法示例骨架：

```markdown
**核心结论：XX 行业已从早期试点进入规模化应用阶段，2020-2025 年市场规模由 X 亿元增长至 Y 亿元，复合增长率为 Z%；其中标的所在的 A 细分市场增速高于行业整体，已成为本轮增长的主要结构性增量。**
```

写作要点：

- 总市场、细分市场、标的可及市场分层写，不要把广义大市场直接当作标的天花板；
- CAGR 必须按首末值复算，写清起止年份；
- 预测值必须标明预测方、年份和口径；
- 数据少时可以用“量 × 价”“存量替换 + 新增需求”“客户数 × 渗透率 × 客单价”做区间测算；
- 不要出现“根据公司整理”“该数为公司自述”“仅作为方向参考”。

### 路径 A：2.核心增长驱动力

**核心结论前置**：先用加粗总论判断增长主要由哪些因素驱动，并给出排序。不要把所有因素并列堆砌。

固定写法：

```markdown
**核心结论：行业增长并非单一技术扩散结果，而是政策制度完善与下游真实需求释放共同作用的结果；其中政策驱动解决准入和规范问题，市场驱动解决付费和规模化问题，技术/成本因素则决定放量节奏。**

（1）政策驱动
**核心结论：……**
一是……
二是……
三是……

（2）市场驱动
**核心结论：……**
一是……
二是……
三是……

（3）其他驱动（按需）
**核心结论：……**
……
```

#### （1）政策驱动

必须写“政策如何改变行业”，而不是罗列政策名称。优先提炼三类演进：

- 战略定位变化：从试点、鼓励、培育到支柱产业、法律保障、专项规划；
- 治理逻辑变化：从“管得住”到“促发展”，从审慎监管到标准化规模运营；
- 政策工具变化：标准体系、统计分类、试点授权、基础设施、准入认证、采购/补贴。

每个细分点都要详写作用机制：政策如何影响空域/准入/预算/客户采购/基础设施/行业标准，而不是只写“政策利好”。

#### （2）市场驱动

必须写“谁愿意付费、为什么现在付费”。优先拆成：

- 存量替代：替代人工、旧设备、低效流程，解决效率、安全、成本问题；
- 增量创造：传统手段无法覆盖的新场景、新功能、新客户；
- 预算和商业闭环：客户是否有持续预算、是否进入常态化采购、是否从试点转向规模运营。

每个痛点都要对应下游场景，避免泛泛写“需求旺盛”。

#### （3）其他驱动（按需）

只有行业确实存在显著变量时才写：

- 技术驱动：核心技术成熟、可靠性提升、产品形态变化；
- 成本驱动：核心部件降价、国产化、规模化制造；
- 供给驱动：基础设施完善、产能释放、运营商/平台开放；
- 国产替代驱动：供应链安全、认证、成本和交付周期改善。

### 路径 B：1.关键配套/基础设施地位

**核心观点前置**：首段必须直接回答“该细分环节为什么是下游场景规模化的核心基础设施或关键配套”。

推荐骨架：

```markdown
**核心观点：在 XX 场景从试点验证走向常态运营的阶段，XX 正成为补齐 XX 短板、支撑 XX 能力的关键配套。**
```

推荐展开：

1. 政策支持层面：写政策从框架性支持到标准、准入、基础设施或强约束落地的变化；
2. 市场需求层面：写原有方案短板、客户真实场景和新方案解决的问题；
3. 技术路线层面（按需）：写高低端、新旧路线或不同方案的优势、局限和分工。

写作要点：

- 先写早期政策或技术的局限，再写新拐点，增强可信度；
- 技术参数必须服务于场景判断，如时延、重量、功耗、精度、成本、可靠性；
- 若两种路线会长期并行，不要写成一方完全替代另一方。

### 路径 B：2.市场规模与增长趋势

沿用路径 A 的市场规模规则，但更强调口径分层：

1. 广义市场：说明行业背景和基础盘；
2. 相关细分市场：说明与标的所处环节直接相关的市场；
3. 配套/可及市场：用装机、客户数、单套价值量、渗透率或配套率解释标的可触达空间；
4. 放量条件：说明基础设施、技术降本、认证、客户预算或下游场景成熟度。

不要把广义行业市场规模直接当作标的市场空间。

## 五、（二）产业链分析

本部分回答“产业链如何分工、核心部件/服务分别干什么、价值和壁垒在哪里、标的卡位意味着什么”。

### 1.产业链概况

**核心结论前置**：第一段必须概括产业链结构、核心瓶颈、价值集中环节和标的所处位置。

推荐骨架：

```markdown
**核心结论：XX 行业产业链可划分为“上游 A/核心零部件/基础资源—中游 B/系统集成/产品制造—下游 C/行业应用/运营服务”。标的公司主要处于中游系统集成与下游场景解决方案环节，其竞争力取决于上游关键部件适配能力、场景 Know-how 与持续运营能力。**
```

#### （1）产业链上游

必须先写加粗核心结论，再写构成与功能。

```markdown
**核心结论：上游决定产品性能、成本和可靠性，是产业链技术壁垒与成本曲线的主要来源。**
```

展开时按“类别：功能 + 重要性 + 壁垒/成熟度”写：

- 原材料/基础资源：说明材料、能源、频谱、数据、算力等基础要素的作用；
- 核心零部件：说明芯片、传感器、电池、射频器件、控制器、算法模块等分别解决什么问题；
- 软件与基础平台：说明操作系统、协议栈、数据库、训练平台、云平台等如何支撑产品能力；
- 测试认证与制造配套：说明认证、检测、代工、工艺等如何构成准入或交付壁垒。

不要只写“上游包括 A、B、C”，必须解释每个东西的功能。

#### （2）产业链中游

必须先写加粗核心结论，再写构成与功能。

```markdown
**核心结论：中游是将上游要素转化为可交付产品或解决方案的环节，竞争力取决于系统集成、工程化、场景适配和交付能力。**
```

展开时说明：

- 整机/产品制造：把核心部件组合成终端产品，决定稳定性、良率、成本和交付；
- 系统集成：解决软硬件适配、接口、可靠性、环境适应性、运维等工程问题；
- 行业解决方案：围绕客户业务流程做定制化配置，是从“卖产品”走向“卖结果”的关键；
- 标的卡位：判断标的在中游的具体角色，是整机厂、系统集成商、平台商，还是方案服务商。

#### （3）产业链下游

必须先写加粗核心结论，再写构成与功能。

```markdown
**核心结论：下游决定行业需求兑现速度和商业化天花板，客户预算、场景成熟度和运营能力直接影响中游产品放量。**
```

展开时说明：

- 终端客户：G 端、央企、大 B、中小 B、C 端分别有什么采购逻辑；
- 应用场景：哪些场景已规模化，哪些仍在试点，哪些只是远期想象；
- 运营服务：运维、数据处理、培训、外包、SaaS/平台服务如何延伸价值；
- 客户集中度与付费能力：下游集中会带来订单确定性，也会带来议价和回款压力。

### 2.产业链洞察与启示

每条启示必须先写加粗总结句，再详写机制、证据和对标的的含义。

固定写法：

```markdown
**第一，产业链价值重心正从单纯制造环节向“产品+场景+运营”的综合服务环节延伸。**
展开：……

**第二，上游核心部件的国产化与降本进度，将直接决定中游产品放量速度和毛利空间。**
展开：……

**第三，下游客户场景越分散，中游企业越需要行业 Know-how 与本地化服务能力构筑壁垒。**
展开：……
```

启示必须满足三点：

1. 来自前文产业链事实，不凭空拔高；
2. 指向投资判断，如价值迁移、壁垒形成、成本下降、需求兑现、议价关系；
3. 落回标的公司卡位，说明其顺势、逆势或仍待验证。

## 六、内部一致性核验矩阵

成稿前逐项核对：

| # | 核验点 | 检查什么 | 不一致时怎么办 |
|---|---|---|---|
| 1 | 输出结构 | 是否从“二、所属行业分析”开始，且只含固定两大部分四个三级标题 | 删除多余标题，尤其“行业定义与研究边界” |
| 2 | 核心结论前置 | 每个细分部分是否都有加粗核心结论，段首是否是论点句 | 补核心结论，或把段落首句改成判断句 |
| 3 | 市场规模口径 | 总市场、细分市场、标的可及市场是否分层，口径是否一致 | 重新标注口径；无法统一时并列说明 |
| 4 | CAGR 与表格 | CAGR 是否按首末年复算，正文与表格数字是否一致 | 以原始首末值重算，修正正文或表格 |
| 5 | 增长驱动排序 | 政策驱动、市场驱动是否都写了，其他驱动是否有真实依据 | 缺项补写；凑数项删除 |
| 6 | 产业链功能 | 上中下游是否都写了核心结论、构成和功能，而不只是列企业名 | 补“功能+重要性+壁垒/成熟度” |
| 7 | 标的卡位 | 是否明确标的位于上游/中游/下游/一体化及其主战场 | 结合资料包和公开信息独立判断，不照抄公司说法 |
| 8 | 洞察启示 | 每条启示是否加粗总结、详写机制，并落回标的 | 把复述性内容改成“规律→推导→标的含义” |
| 9 | 禁用表达 | 是否出现“根据公司整理”“该数为公司自述”“仅作为方向参考”等 | 删除或改为来源说明/待核实事项 |
