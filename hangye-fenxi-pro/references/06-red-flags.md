# 行业分析红旗库

本红旗库只服务于“二、所属行业分析”的固定结构，用来识别看起来专业但经不起投委会追问的叙事陷阱。红旗不是结论错误，而是提示某个判断需要更硬证据、口径修正或降级表述。

使用方法：写完 `市场规模与增长趋势`、`核心增长驱动力`、`产业链概况`、`产业链洞察与启示` 后逐项扫描。命中的红旗要转化为核查动作或正文修订，不要写“无”。

## 一、结构红旗

| 红旗现象 | 为什么危险 | 核查/改写动作 |
|---|---|---|
| 开篇出现“行业定义与研究边界”标题 | 与本技能固定输出结构冲突，破坏用户要求的范文式章节 | 删除该标题，只把边界判断自然融入市场规模口径和产业链卡位 |
| 输出竞争格局、风险分析、投资判断小结等额外同级章节 | 把行业分析扩成完整行研，偏离立项报告该部分的篇幅与结构 | 将必要判断压缩进增长驱动或产业链启示 |
| 小节没有加粗核心结论，直接铺数据或政策 | 投委会读不出判断，只看到资料堆砌 | 在每个细分部分首段补“核心结论” |

## 二、市场规模与增长趋势红旗

| 红旗现象 | 为什么危险 | 核查/改写动作 |
|---|---|---|
| 只引用广义大行业规模，不写标的相关细分市场 | 容易把宏观大盘当作标的可及市场，夸大天花板 | 按总市场、细分市场、标的相关市场分层 |
| 用异常低点或试点初期年份计算 CAGR | 把恢复性反弹包装成结构性高增长 | 选正常年份重算，或并列两个 CAGR 说明差异 |
| CAGR 与首末值不一致 | 投委会会直接复算，数据错误削弱全文可信度 | 用 `reconcile_check.py` 或手工复算 |
| 远期预测倍数跳跃大，但没有中间年份和关键假设 | 数字像募资故事，不像独立研究 | 补渗透率、单价、客户数、装机量等假设，或降级为区间 |
| 正文出现“根据公司整理”“该数为公司自述”“仅作为方向参考” | 公司自述不应成为行业空间核心证据，也破坏正式报告质感 | 改用权威来源；无法验证则放待核实事项 |
| 写“市场空间巨大、前景广阔”但没有规模、增速和驱动机制 | 空泛乐观 | 用具体数字、CAGR、细分占比和驱动因素替代 |

## 三、政策驱动红旗

| 红旗现象 | 为什么危险 | 核查/改写动作 |
|---|---|---|
| 政策原文只是“鼓励、支持、引导”，正文写成“强制、刚性、明确要求” | 夸大政策约束力，误导行业阶段判断 | 对照政策原文，力度不够时降级为方向性支持 |
| 罗列十几条政策但不归纳演进规律 | 政策清单不等于分析 | 先写战略定位、治理逻辑、政策工具的变化，再用表格支撑 |
| 只写政策利好，不写合规、准入、标准和监管成本 | 单边论证 | 同时说明政策如何提高门槛或改变竞争 |
| 地方试点政策被写成全国性趋势 | 试点不等于普遍放开 | 写明区域、试点阶段和复制条件 |

## 四、市场驱动红旗

| 红旗现象 | 为什么危险 | 核查/改写动作 |
|---|---|---|
| 把政策鼓励直接等同于真实付费需求 | 政策热不代表客户愿意长期买单 | 区分政策驱动和客户预算驱动 |
| 需求证据全部来自标的管理层访谈 | 样本有天然乐观偏差 | 找下游客户、行业协会、招投标、年报等独立证据 |
| 只写“效率提升、降本增效”，不写具体痛点和客户场景 | 需求无法验证 | 对应到客户、流程、成本、安全、覆盖范围或数据价值 |
| 把试点项目写成规模化商业化 | 试点验证和常态采购是不同阶段 | 标明“试点/示范/规模交付/常态运营” |

## 五、产业链概况红旗

| 红旗现象 | 为什么危险 | 核查/改写动作 |
|---|---|---|
| 上中下游只列企业名，不解释部件或服务功能 | 读者不知道钱和壁垒在哪里 | 每个类别补“功能+重要性+壁垒/成熟度” |
| 标的公司产业链位置照抄公司说法 | 公司常倾向写“全产业链布局”，不等于真实壁垒 | 根据收入来源、产品交付、客户价值和关键能力独立判断 |
| 上游核心部件成本或国产化缺口没有写 | 无法判断中游放量和毛利空间 | 补成本占比、国产化率、供应格局或认证难度 |
| 下游场景都写成“快速增长” | 不同场景商业化阶段差异很大 | 区分成熟场景、快速拓展场景和培育场景 |
| 产业链价值量和市场规模混加 | 终端市场、部件市场、服务市场不可直接相加 | 明确产业链层级，不同层级分开表述 |

## 六、产业链洞察与启示红旗

| 红旗现象 | 为什么危险 | 核查/改写动作 |
|---|---|---|
| 启示只是复述“上游重要、中游集成、下游应用” | 没有投资含义 | 改成价值迁移、瓶颈环节、降本节奏、客户结构等规律 |
| 启示没有落回标的公司 | 行业分析与项目投资脱节 | 每条启示增加“对标的公司而言”或自然落点 |
| 把对标的有利的趋势写成确定性结论 | 结论被投资意愿污染 | 给出条件式表达和待验证变量 |
| 没有写反向约束 | 只讲机会不讲产业链制约 | 补写上游成本、下游预算、标准认证、客户集中等约束 |

## 七、组合红旗

多条红旗同时出现时，需要在正文中降级判断或补充核查动作：

- **大市场口径 + 无细分市场 + 标的卡位模糊**：行业盘子可能与标的收入无关。必须重建 TAM/细分/SAM 层级。
- **政策热 + 试点项目 + 无客户预算证据**：需求可能仍停留在示范阶段。市场驱动部分必须补真实付费逻辑。
- **需求高增 + 上游降本未兑现 + 中游竞争者增多**：行业规模增长不等于标的毛利改善。产业链启示中需点出成本和竞争压力。
- **全产业链表述 + 收入集中单一环节 + 核心能力未证明**：公司“全产业链布局”可能只是宣传口径。产业链卡位要以收入和交付能力为准。
