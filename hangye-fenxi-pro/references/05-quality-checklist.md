# 质量自检清单与交付标准

交付前逐项自检。任何一项不通过，修订后再交付。自检时把自己切换为投委会里最挑剔的委员：他会复算你的 CAGR，追问政策是否真有约束力，也会问标的到底卡在产业链哪一环。

## 一、结构合规

**1. 是否从固定标题开始**

- [ ] 成稿第一个标题是 `二、所属行业分析`
- [ ] 前面没有“XX行业分析”“行业定义与研究边界”等大标题
- [ ] 没有输出“行业定义与研究边界”小节

**2. 是否只保留固定两大部分四个三级标题**

- [ ] `（一）行业发展背景与现状`
- [ ] `1.市场规模与增长趋势`
- [ ] `2.核心增长驱动力`
- [ ] `（二）产业链分析`
- [ ] `1.产业链概况`
- [ ] `2.产业链洞察与启示`
- [ ] 未擅自新增同级的竞争格局、风险分析、投资判断小结等章节

**3. 标题编号是否统一**

- [ ] 编号层级为 `二、` → `（一）` → `1.` → `（1）` → 段内“一是/二是/三是”
- [ ] 无跳级、重号、标题逻辑重复

**3A. `.docx` 公文版式是否符合范文**

- [ ] 页面为 A4 纵向
- [ ] 上下页边距约 1 英寸，左右页边距约 1.25 英寸
- [ ] 正文及各级标题基准字号为 16pt
- [ ] 段落固定 28 磅行距
- [ ] 段落首行缩进约 2 个中文字符
- [ ] `二、所属行业分析` 使用黑体 16pt，可不加粗
- [ ] `（一）（二）` 层级使用楷体_GB2312 16pt 加粗
- [ ] `1.`、`（1）`、正文、核心结论使用仿宋_GB2312 16pt
- [ ] 表格表头加粗，表格正文默认不加粗

## 二、核心结论前置

**4. 每个细分部分是否有加粗核心结论**

- [ ] 市场规模与增长趋势有加粗核心结论
- [ ] 核心增长驱动力有加粗总论
- [ ] 政策驱动有加粗核心结论
- [ ] 市场驱动有加粗核心结论
- [ ] 其他驱动（如有）有加粗核心结论
- [ ] 产业链概况有加粗核心结论
- [ ] 上游、中游、下游分别有加粗核心结论
- [ ] 产业链洞察与启示每条均以加粗总结句开头

**5. 加粗内容连读是否构成摘要**

- [ ] 加粗内容能说明行业阶段、规模增速、增长驱动、产业链结构和标的卡位
- [ ] 加粗句不是空泛口号，后文都有证据支撑
- [ ] 证据句、企业名录、表格正文没有滥用加粗

## 三、行业发展背景与现状

**6. 市场规模与增长趋势是否扎实**

- [ ] 写了行业总规模、近年增长和 CAGR
- [ ] 写了标的相关细分市场，而不只写广义大市场
- [ ] CAGR 已按首末值复算
- [ ] 历史数据和预测数据区分清楚
- [ ] 数据来源、时间、口径明确
- [ ] 无“根据公司整理”“该数为公司自述”“仅作为方向参考”

**7. 增长趋势是否有结构判断**

- [ ] 说明增长来自总量扩张、细分渗透、量价变化、下游客户增加或服务化延伸中的哪几类
- [ ] 判断行业处于导入期、成长期、成熟期或分化期，并给出理由
- [ ] 未使用“前景广阔、潜力巨大、大有可为”等空泛词替代分析

**8. 核心增长驱动力是否完整**

- [ ] 必写政策驱动
- [ ] 必写市场驱动
- [ ] 如写技术/成本/供给/国产替代驱动，确有证据，不是凑数
- [ ] 总论里对驱动因素有排序或主次判断

**9. 政策驱动是否写出机制**

- [ ] 不只是政策罗列，写了政策层级、治理逻辑或工具变化
- [ ] 每条政策影响都落到准入、标准、空域、采购、预算、基础设施或监管成本等具体机制
- [ ] 政策力度未夸大；倡导性政策未写成强制约束

**10. 市场驱动是否写出真实需求**

- [ ] 区分存量替代和增量创造
- [ ] 写明下游客户是谁、痛点是什么、为什么愿意付费
- [ ] 写明需求是试点验证、常态化采购还是远期培育
- [ ] 标的相关场景得到重点展开

## 四、产业链分析

**11. 产业链概况是否总起到位**

- [ ] 首段概括“上游 A—中游 B—下游 C”
- [ ] 明确标的公司处于上游/中游/下游/一体化，以及主要侧重环节
- [ ] 写出核心瓶颈或价值集中环节

**12. 上游是否写出功能**

- [ ] 上游有加粗核心结论
- [ ] 写明核心材料、零部件、芯片、算法、软件、认证或基础资源等构成
- [ ] 每类构成都解释了功能和重要性
- [ ] 写明技术/成本/成熟度/国产化/供应壁垒中的关键点

**13. 中游是否写出功能**

- [ ] 中游有加粗核心结论
- [ ] 写明整机制造、系统集成、平台产品、解决方案或工程交付的角色
- [ ] 解释中游如何把上游要素转化为可交付产品或服务
- [ ] 标的若处于中游，说明其壁垒来自全栈自研、集成能力、场景适配、客户资源还是交付能力

**14. 下游是否写出功能**

- [ ] 下游有加粗核心结论
- [ ] 写明终端客户、应用场景、运营服务和数据价值
- [ ] 区分成熟应用、快速拓展和试点培育场景
- [ ] 说明下游需求如何影响中游放量和标的成长

**15. 产业链洞察与启示是否有投资含义**

- [ ] 每条启示先写加粗总结，再详写
- [ ] 启示不是复述产业链，而是提炼价值迁移、瓶颈环节、降本逻辑、客户格局或服务化趋势
- [ ] 每条启示都落回标的公司的卡位、机会或待验证事项
- [ ] 启示数量以 2-4 条为宜，宁少而深，不凑数

## 五、数据与来源

**16. 数据是否可追溯**

- [ ] 每个规模、增速、占比、成本、国产化率等数字能回答“谁发布、哪一年、什么口径”
- [ ] 第三方预测点明机构和发布时间
- [ ] 表格来源与正文来源一致

**17. 公司资料使用是否克制**

- [ ] 公司资料只用于判断标的产品、客户和产业链位置
- [ ] 公司自述行业数据未直接作为关键行业结论
- [ ] 无公司资料免责声明式措辞污染正文

**18. 机械校验是否完成**

- [ ] 涉及市场规模、CAGR、占比、表格时，已运行 `python scripts/reconcile_check.py 行业分析.md`
- [ ] FAIL 项已回原始资料核实，不是反向改数字消灭报错
- [ ] REVIEW 项已人工复核

## 六、语言与风格

**19. 是否符合立项报告语气**

- [ ] 正式、客观、克制，无口语和营销语
- [ ] 采用书面公文口吻，原则上不用“我们认为”“笔者认为”
- [ ] 段首论点句清晰
- [ ] 政策、数据、产业链都先归纳规律再展开明细
- [ ] 未出现“必然、一定、毫无疑问、确定性极强、强烈推荐”等绝对化表达

**20. 是否真正服务投委会判断**

- [ ] 全文能回答行业盘子、增长真实性、产业链价值分布、标的卡位四个问题
- [ ] 不把行业分析写成行业科普
- [ ] 不把公司优势写成未经验证的行业结论
- [ ] 对仍需核实的数据或假设保持审慎

## 交付物标准

最终交付的行业分析章节至少包含：

1. 固定标题体系；
2. 各小节加粗核心结论；
3. 市场规模、增长趋势及关键数据来源；
4. 政策驱动和市场驱动的详细机制；
5. 上游、中游、下游产业链构成及功能说明；
6. 标的公司产业链位置判断；
7. 产业链洞察与启示；
8. 必要表格和数据来源说明。
