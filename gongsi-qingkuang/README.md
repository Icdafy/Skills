# gongsi-qingkuang — 立项报告「公司情况」章节生成技能

把一家拟投资公司的**尽调资料包＋会议纪要**，结合全网权威检索，炼成股权投资立项报告的「**四、公司情况**」章节。写作口径对齐一级市场投资机构内部金标准范文：客观、审慎、事实优先、证据可溯源，优势与瑕疵同台。

供投委会回答一个问题：**这家公司的主体、股权、团队、资源与合规状况，是否构成一笔可以推进的投资的基础条件。**

## 输出（双件套）

| 交付物 | 说明 |
| --- | --- |
| 章节正文 | 骨架、句式、表格全部对齐范文（早期公司=颗粒度细的逐次重演写法；成长期公司=汇总表写法）；默认 Markdown，可一键渲染公文排版 .docx |
| 待补充资料及后续核查事项清单 | 随稿交付、正文之外；每条写清查什么文件、走什么渠道、问什么问题，可直接转给尽调团队 |

资料里的每个事实只有两个合法去向：进入正文/表格（可溯源），或进入清单（可执行）——第三种去向"悄悄消失"不存在。

## 输入三源

| 来源 | 独家供给 |
| --- | --- |
| 尽调资料包（工商资料、股权表、章程、审计报告、专利证书、花名册、BP、投资协议） | 全部硬数据 |
| 会议纪要／访谈纪要 | 书面资料查不到的软信息：子公司真实用途、代持形成原因、技术真实来源、公司对财务问题的解释、上市时间表、在手订单——一律挂"据访谈／公司表示"口径 |
| 联网检索 | 三大必检：机构股东背景识别（"机构简称，资金性质"格式）、客户供应商背景识别、官方规则与公开风险核验 |

## 使用方式

装载技能后上传资料，直接说：

- "写一下XX公司的公司情况"
- "根据资料包和会议纪要出公司情况章节"
- "把股权结构/历史沿革/核心团队整理成立项报告口径"

技能自动完成：建事实台账 → 榨取会议纪要 → 联网补缺与背景增强 → 公式勾稽＋十四对三角验证 → 按骨架起草 → 红旗扫描 → 语言红线扫描 → 机械勾稽自检 → 交付。

## 章节骨架（默认与范文四节制对齐）

```
四、公司情况
（一）基本信息        工商信息 / 核心团队 / 人员及组织架构 / 关联公司* / 知识产权 / 荣誉及资质* / 前五（十）大客户及供应商
（二）股权变动情况    股东结构（含背景列+穿透表+代持披露）/ 历史股权变动 / 历史融资及估值情况
（三）财务数据        核心财务数据 / 存在问题（及对策）/ 财务预测
（四）上市规划*
带 * 为条件节；增配节（默认不启用）：合规信用风险事项、公司情况综合判断
```

## 语言红线（零容忍）

1. **禁用否定-肯定对照连词族**："不是……而是""并非……而是""不仅……而且""不但……还"等一律禁止；直接写肯定半句，对比拆成两个事实句，转折只用"但"。
2. **称谓只有两种**：默认主语"公司"，点名用公司简称；全文零"标的公司""该标的""目标公司"。
3. **结论先行**：每段首句点明该段核心，零铺垫、零"值得注意的是"式引子。

配套硬规则：正文只允许四类句子（引导句/事实句/识别句/判断+核查句）；瑕疵白描＋核查出口（0元转让照实写）；口径三分法（审计报告/公司表示/本方判断永不混写）；缺口写"相关资料尚未提供"，禁止编造任何数字。

## 文件结构

| 文件 | 用途 |
| --- | --- |
| `SKILL.md` | 触发条件、执行顺序、骨架、语言红线、写作准则 |
| `references/structure.md` | 施工图：事实台账、会议纪要挖掘清单、三角验证矩阵（14对）、逐节"写什么/为什么/怎么写"、裁剪规则 |
| `references/writing-craft.md` | 语言红线细则（禁用句式改写对照表）、四类合法句子、段落四拍、句式库、质检清单（17项） |
| `references/data-and-tables.md` | 计算公式、口径与单位、勾稽自检清单、联网三大必检、标准表模板 T1–T15 |
| `references/red-flags.md` | 按文档位置索引的红旗模式库（现象→为什么危险→核查动作）＋组合拳规则 |
| `references/gold-examples.md` | 范文文体指纹与 14 个高质量段落逐一拆解 |
| `scripts/build_docx.py` | 内容 JSON → 公文排版 .docx（仿宋三号、首行缩进、固定行距 28 磅） |
| `scripts/reconcile_check.py` | 机械勾稽核验：股权求和=100%、人员分项=总数、客户合计、资产负债恒等式、毛利率反算等 |
| `scripts/extract_docx.py` | 读取 .docx 资料包，逐块输出段落与表格便于建台账 |
| `assets/content_skeleton.json` | content.json 骨架样例 |
| `evals/evals.json` | 四个回归用例（含语言红线断言与会议纪要专项） |

## 脚本用法

```bash
# 勾稽核验（仅标准库，任何 Python 可跑；FAIL 时退出码 2）
python scripts/reconcile_check.py content.json

# 生成 Word（依赖 python-docx）
python scripts/build_docx.py content.json output.docx

# 读取 docx 资料包（依赖 python-docx）
python scripts/extract_docx.py "某公司-尽调资料.docx" out.txt
```

## v2.0 升级要点（2026-07）

- 新增**语言红线**并置于全流程第一优先级：禁用"不是而是"类否定-肯定对照连词族（附逐条改写示范）、禁用"标的公司"类称谓、结论先行，质检清单前四项专查语言。
- 新增**会议纪要挖掘协议**：十类纪要独家信息对号入座到章节位置，每条"公司说法"先分类（可书面验证→生成核查任务／仅口头→挂口径照录）再落笔；三角验证矩阵扩至 14 对（新增纪要↔书面文件互锁）。
- 联网检索聚焦为**三大必检**，股东背景列升级为标准动作（"机构简称，资金性质"格式）。
- 默认骨架回归范文四节制；合规节与综合判断节改为增配节，风险线索全部汇入随稿待核查清单。
- 基于范文逐字复核补齐**文体指纹**：称谓两分法、转折只用"但"、引导句冒号收尾、客户供应商节纯表格、财务分析段以简称开头等。
- 修复 `reconcile_check.py` 合计行识别缺陷（合计标记在序号列时曾被当明细重复求和），并支持"前10大小计/总收入"两级合计与"收入额/价税合计"表头；已用两篇范文真实数据完成正反向冒烟测试。
