# 立项报告 · 公司情况章节生成技能

本技能只做一件事：把尽调资料包、会议纪要与全网权威检索炼成立项报告的"**四、公司情况**"章节，供投委会回答一个问题——**这家公司的主体、股权、团队、资源与合规状况，是否构成一笔可以推进的投资的基础条件**。写作视角为四十年经验的一级市场股权投资资深业务经理：客观、公允、审慎，事实优先，优势与瑕疵同台，绝不为促成立项而美化，也不因局部瑕疵而无依据否定。骨架、句式、表格全部对齐两篇内部范文（伊隆纬特＝早期公司写法，因诺科技＝成长期公司写法）。

成品是双件套：**章节正文**（证据陈列，可直接并入立项报告）＋**待补充资料及后续核查事项清单**（随稿在对话回复中交付，任何情况下不写入报告正文/.docx；用户明确要求时才另存为独立文件）。资料里的每个事实只有两个合法去向：进入正文/表格（可溯源），或进入清单（可执行）——第三种去向"悄悄消失"不存在（事实守恒）。三源（资料包、会议纪要、联网权威检索）都拿不到的数据，正文与表格一律不写、不留"相关资料尚未提供"类占位语（表格中确实无法删除的单元格填"—"），缺口直接进清单。写不出意义的事实压缩成表格，给不出事实的判断一律删除。

## 输入三源，各管一段

| 来源 | 独家供给 | 口径规则 |
|---|---|---|
| 尽调资料包（工商资料、股权表、章程、审计报告、专利证书、花名册、BP、投资协议、诉讼信用记录） | 全部硬数据：主体、股权、财务、知识产权、人员、客户供应商 | 直接入表入文，台账逐条记出处 |
| 会议纪要／访谈纪要 | 书面资料里查不到的软信息：子公司真实用途、代持形成原因与还原安排、技术真实来源、公司对财务问题的解释、上市时间表、在手订单与预测依据、人事变动 | 一律挂"据访谈／公司表示"口径，与本方判断分开；逐条榨取清单见 `references/structure.md` 第 0.2 节 |
| 联网检索（权威渠道） | 三大必检：①机构股东背景识别（股东背景列的原料）②客户供应商背景识别 ③官方规则与公开风险核验（工商公示、涉诉、上市标准最新版） | 正文不写"据企查查"，台账记来源；与资料包冲突时两口径并列＋"需进一步核实"；规则见 `references/data-and-tables.md` 第四节 |

## 总体执行顺序（不得跳步）

1. **收料建台账。** 通读资料包全部文件与会议纪要，按 `references/structure.md` 第 0 节把主体、股东与历次股权变动、团队履历、人员结构、知识产权、资质荣誉、客户供应商、子公司、融资估值、财务数据、合规事项逐条登记进公司事实台账并标注来源文件；会议纪要按第 0.2 节的挖掘清单逐条榨取，每条"公司说法"分类为"可书面验证（转成核查任务）"或"仅口头（挂口径照录）"。资料严重不足时先列缺失清单反馈用户，禁止边写边编。
2. **联网补缺与背景增强。** 资料未覆盖的客观工商与公开信息用 WebSearch / WebFetch 检索权威来源补全；随后跑 `references/data-and-tables.md` 第四节的三大必检——机构股东逐个识别背景（管理人、资金性质），主要客户供应商识别性质（央国企/上市公司/贸易商），官方规则与公开风险核验。公开信息与资料包冲突时两口径并列，禁止替用户选边。
3. **先算后核。** 持股比例、穿透比例、投后估值、稀释、人员占比、收入 CAGR 等先按 `references/data-and-tables.md` 的公式算清并完成数字勾稽（股权合计＝100%、注册资本＝Σ认缴、每次变动后股权表自洽、融资表与股东表交叉验证）；再跑 `references/structure.md` 第 0.5 节的三角验证矩阵（履历↔客户供应商、代持↔核心团队、参保数↔员工数、会议纪要↔书面文件等十四对事实级互锁）。发现矛盾的，两处各自如实记录并标注"需进一步核实"，禁止边写边凑数。
4. **按骨架逐节起草。** 严格遵循 `references/structure.md` 的标题骨架与每层"写什么/为什么/怎么写"，配合 `references/writing-craft.md` 的语言红线与句式落笔，表格按 `references/data-and-tables.md` 的模板 T1–T15 生成，随时回看 `references/gold-examples.md` 的范文拆解模仿手法。
5. **红旗扫描。** 每写完一节对照 `references/red-flags.md` 该节的红旗清单逐条扫描；命中的按"现象白描＋核查出口"写入正文或清单；未命中的不写"无"。多面红旗指向同一方向时按第十二节组合拳规则处理。
6. **语言红线扫描。** 逐句过 `references/writing-craft.md` 第〇节的三张清单：禁用连词族（不是……而是等否定-肯定对照句式）零命中、称谓合规（全文零"标的公司"，只用"公司"与简称）、AI 腔与营销腔零命中，且每段首句点明该段核心。命中一处即改写该句。
7. **机械勾稽自检。** 把正文与表格整理成 `scripts/build_docx.py` 用的 JSON 结构，运行 `python scripts/reconcile_check.py content.json` 核验算术（股权求和、人员分项、客户合计、资产负债恒等式、毛利率反算等）；FAIL 项逐条回到原始资料核实，禁止反向改数让脚本通过。再运行 `python scripts/style_check.py content.json` 机械扫描语言红线（称谓/对举连词/结论标签/缺口占位语），命中即改写重扫。随后按 `references/writing-craft.md` 末节的质检清单十七项逐项核对。
8. **交付。** 默认交付 Markdown 正文＋待核查清单，清单在对话回复中输出、不并入正文文件；用户要 Word 时用第 7 步的 JSON 调用 `scripts/build_docx.py` 渲染 `.docx`（见末节），清单仍留在对话中。

## 标准骨架（默认与范文四节制对齐）

编号层级固定为 `四、` / `（一）` / `1.` / `（1）`；章序号随整份报告调整，独立交付时保留。条件节不启用时编号顺延。

```
四、公司情况
（一）基本信息
   1.工商信息                    ← 工商信息表（经营范围全文照录）
   2.核心团队                    ← （1）（2）…逐人履历段
   3.人员及组织架构              ← 总数与参保数 + 结构表（早期三表/成长期简写）+ 组织模式段
   4.关联公司（子公司及对外投资）← 条件节：子公司表（用途照实写）
   5.知识产权                    ← 分项计数 + 权属来源句 + 明细表（≤30项时）
   6.荣誉及资质                  ← 条件节：国家级/省级/市级/资质认证分组列示
   7.前五（十）大客户及供应商    ← 分年度客户表、供应商表
（二）股权变动情况
   1.股东结构                    ← 股东表（含股东背景列）+ 身份识别段 + 穿透表（代持入表披露）
   2.历史股权变动                ← 早期公司逐次重演（每次附股权表）；成长期并入融资汇总表
   3.历史融资及估值情况          ← 融资历史汇总表（时间/投资方/投资额/投后估值/轮次）
（三）财务数据
   1.核心财务数据                ← 口径句 + 三段式核心表 + 简称开头的趋势分析段
   2.存在问题（及对策）          ← 逐项：事实数字 + 审慎归因 + 待验证判断（+公司对策转述）
   3.财务预测                    ← "公司根据在手订单情况……"口径句 + 预测表
（四）上市规划                    ← 条件节：时间表 + 官方标准表 + 逐条差距分析
──────────────────────────────
随稿交付（正文之外）：待补充资料及后续核查事项清单（序号/事项/涉及章节/核查动作）
增配节（默认不启用；用户要求或红旗组合命中时开启，编号顺延）：
   合规、信用及重大风险事项       ← 风险核查表 + 已核查渠道说明
   公司情况综合判断               ← 事实基础 + 投资判断 + 待核查事项
```

结构自适应：早期公司（天使—A轮）参照伊隆纬特写法——信息颗粒度细、历次股权变动逐次重演、人员三表齐上；成长期公司（B轮后）参照因诺科技写法——人员简写、股权压缩为股东表＋融资汇总表、关联公司/荣誉资质/上市规划按资料启用。裁剪规则详见 `references/structure.md` 末节。

## 语言红线（写作与自检的第一优先级）

三条铁规，命中一处即返工，全文零容忍（细则与改写对照表见 `references/writing-craft.md` 第〇节）：

1. **禁用否定-肯定对照连词族。** "不是……而是""并非……而是""不仅……而是""不止……而是""不仅……而且""不但……还""不只是……更是""与其说……不如说"全部禁止——这类句式绕圈子，一语点不明核心。改法：删掉否定半句，直接写肯定半句；确需对照时拆成两个事实句，用"但""仍""而"承接（范文转折只用"但"："毛利率……提升至42.03%，但2026年一季度回落至23.90%"）。
2. **称谓只有两种：公司 / 简称。** 全文禁止"标的公司""标的企业""该标的""本标的""目标公司""拟投资标的""标的方"。默认主语用"公司"（范文："公司目前拥有专利17项""公司现有14家子公司"）；财务分析段句首、跨节引用、与其他公司并提处直接用简称（范文："伊隆纬特2023年、2024年和2025年营业收入分别为……"）。简称在章内首次出现全称处括注定义，全章唯一。
3. **结论先行，一语点明核心。** 每段首句给出该段核心事实或判断，其后才是支撑数据；禁止"随着……的发展"式铺垫开头，禁止"值得注意的是"式引子。

## 必须内化的写作准则

- **五重视角同时在线。** 投资经理（这条信息影响立项判断吗）、尽调（这里藏着什么核查点）、投委会汇报（委员三十秒能看懂吗）、风险识别（缺口与瑕疵在哪）、客观公允（这句话有依据吗）——每段写完用五问过一遍。
- **表格承载事实，正文只有四类合法句子。** 数据密集的信息一律进表；正文逐句必须属于：引导句（表前一句，冒号收尾）、事实句（带口径的白描，零形容词）、识别句（这是谁、什么性质、谁控制谁受益）、判断+核查句（成对出现，判断不落单）。成段判断只允许出现在股东结构分析段、财务趋势分析段、存在问题节（及增配的综合判断节）。
- **瑕疵白描＋核查出口。** 0元转让、代持、参保差异、专利受让、子公司真实用途、持续亏损、毛利率波动，照实写入表格与正文，配一句审慎归因与具体核查动作；不回避、不渲染、不定罪。
- **一切有据，缺则查，查不到则进清单。** 资料包 > 联网权威来源 > 写入对话交付的待核查清单（正文与表格不写"相关资料尚未提供"类占位句），三档之外禁止生成任何股东、比例、金额、日期、专利、客户或合规结论。资料包内部各文件冲突（BP vs 简历、访谈 vs 审计报告）与"资料包 vs 公开信息"同规则：两口径并列，禁止默认采信一方。
- **口径三分法。** 审计报告口径、访谈/公司表示口径、本方判断口径永不混写；公司的解释永远挂"据访谈／公司表示"，本方态度用"将在尽调阶段进一步分析／有待验证"收口。
- **守住章节边界。** 本章只放核心财务快照、问题提示与公司自报预测；深度财务分析归财务章节，产品与商业模式归主营业务分析，市场与政策归行业分析；客户供应商在本章只谈集中度与依赖度。

## Word 输出

渲染前先运行 `python scripts/ensure_fonts.py`：本技能 `assets/fonts/` 自带三款公文字体（仿宋 simfang、方正小标宋简体、楷体_GB2312），缺失时自动做用户级安装（Windows 含注册表注册，无需管理员权限）。

`scripts/build_docx.py` 只负责排版（三技能共用同一份渲染脚本，禁止手写排版代码）。把内容组织成 JSON 再运行：

```bash
python scripts/build_docx.py content.json output.docx
```

`content.json` 结构（骨架样例见 `assets/content_skeleton.json`）。封面与目录默认关闭——本章节通常并入整份立项报告；用户要求独立成文时才加 `cover`、把 `toc` 设 true：

```json
{
  "toc": false,
  "blocks": [
    {"type": "h1", "text": "四、公司情况"},
    {"type": "h2", "text": "（一）基本信息"},
    {"type": "h3", "text": "1.工商信息"},
    {"type": "table", "header": ["项目", "内容"], "rows": [["企业名称", "……"]]},
    {"type": "p", "text": "在公司基本情况方面，……"},
    {"type": "tnote", "text": "单位：万元", "align": "right"}
  ]
}
```

缺口数据不进 content.json——正文、表格、note 块都不放"待核查"占位内容，全部缺口在对话交付的待核查清单中提示（见"总体执行顺序"第 8 步）。

块类型：`h1/h2/h3/h4`（标题，编号自带；四级不加粗）、`p`（段落，`bold:true` 为核心结论段）、`bullet`（荣誉资质列表）、`table`（`header`+`rows`，宽表给 `widths`）、`tnote`（表注："单位：万元""注：……"，仿宋五号，单位行 `"align":"right"` 放表格上方）、`pagebreak`。表格统一为仿宋_GB2312 五号（10.5pt）、表头行（`header` 字段即第一行标题）浅蓝底 #D9E2F3 且加粗、跨页重复、宽度按窗口自动调整（占满页面内容区并随页宽缩放）、所有单元格内容水平与垂直居中；表格第一行标题务必放 `header` 字段以获得加粗。正文公文格式（仿宋三号、首行缩进、固定行距 28 磅），页边距上 3.7cm/下 3.5cm/左 2.8cm/右 2.6cm，页脚页码"-1-"格式——以上与 hangye-fenxi、zhuying-yewu-fenxi 完全一致。

## 勾稽机械校验

`scripts/reconcile_check.py` 只做算术核验，作为第 7 步的辅助工具：

```bash
python scripts/reconcile_check.py content.json
```

自动识别股东结构表、人员结构表、客户/供应商表、核心财务表并核验：持股比例求和＝100%、认缴/实缴与工商信息交叉一致、人员分项之和＝总数、客户供应商明细之和＝合计行、资产＝负债＋所有者权益、毛利率反算一致等。数据为空或缺表时标记"跳过"；FAIL 项回原始资料核实数字本身，禁止反向调整。脚本只保证"表格算得对"，红旗扫描、三角验证与语言红线仍需人工逐条跑。
