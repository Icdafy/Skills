# 强制字体方案（缺少公开授权，尚未实施）

本次要求是让七项技能各自携带并实际使用指定字体，能够独立安装。目标未缩小为只写字体名称或只检查本机安装。

维护者确认的字型映射：中文大标题沿用方正小标宋简体、一级标题黑体、二级标题楷体_GB2312、正文等仿宋_GB2312；页码保留宋体，数字与英文保留Times New Roman。具体位置仍以各技能原版式规则为准，不改字号、缩进、行距、模板及业务规则。

实现需覆盖：

1. 七项技能各自带完整且获准再分发的字体资源，物理复制，无跨技能依赖或符号链接；保留字体原版权及许可，代码许可不覆盖字体。
2. 以实际族名、文件摘要和许可记录核对资源；调用时自动加载或按支持系统做用户级安装，不下载未知字体，不静默改用其他字型。
3. 生成器和字体检测使用同一资源契约。需要的字体未就绪时，先执行安装/加载并核验；仍失败则明确失败，不能交付伪装成正确版式的文档。
4. DOCX嵌入按字体许可标志执行。提供的方正小标宋fsType=2，当前嵌入器会拒绝；不能改标志绕过。应使用获许可的安装/渲染方式，并验证真实标题字形，不能承诺任何未验证客户端都必定显示。
5. 仓库、独立ZIP、来源许可记录、索引、共享副本、安装说明和检查规则同时更新。旧字体排除策略只有在授权确定后才调整，不以“关掉检查”让公开包假通过。
6. 保留原375测试名称与有效版式断言，必要资源契约变化先列依据，再做字体资源正负测试、实际渲染及仓库外独立安装验证；原3轮证据原样保留，不当作新增字体方案的验证结果。

完全无字体的目标机器还需要宋体和Times New Roman资源才能保持全部原版式；当前只提供了三个中文字体文件，黑体仅在本机Windows发现。维护者已答复“没有此授权，或尚不清楚”，因此上述步骤保留为后续实施范围，当前不公开复制字体。须先取得覆盖实际文件及分发方式的授权，或由维护者改变字体/分发范围；没有擅自更换指定字体。
