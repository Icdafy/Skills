# 立项报告｜主营业务分析

## 首先询问阶段，再使用固定模板

**每次为新项目调用本技能，首先询问：“这次项目采用早前期（伊隆纬特）还是中后期（因诺科技）模板？”等待用户回答后再起草。** 用户已在本轮当前项目明确回答的，直接复用答案；三个技能共用同一阶段。不得用融资轮次、规模或业务数量自动推断。安装维护和纯格式修复不触发选模板询问。

用户选择后必读 [阶段模板执行规则](references/stage-template-workflow.md)，只加载对应的 [早前期标题模板](references/template-early.md) 或 [中后期标题模板](references/template-mid-late.md)，实际骨架位于 `assets/templates/early.json`、`assets/templates/mid-late.json`。**普通标题、层级、顺序固定；仅填写已定义的个案变量和重复组。** 根据当前公司资料包逐标题撰写，原案例事实不移植。缺资料先列缺口，不编造、不交付空节。

先用 `python scripts/stage_template.py init --stage early --output 任务目录/draft.json` 生成工作骨架（中后期改为 `mid-late`）；完成标题变量绑定和正文后必须运行 `python scripts/stage_template.py check 任务目录/content.json`。固定模板优先于下文及旧参考中的示例结构；复核时修订正文论证，不自行改题。详细填空、跨Agent降级核对与明确改模板的处理见执行规则。

## 调用与跨 Agent 运行

本技能采用标准 `SKILL.md`（`name` / `description`）入口，支持自然语言匹配或在宿主技能列表中显式选择。安装、迁移或触发异常时读取 [跨 Agent 安装与调用](references/agent-compatibility.md)，按实际产品版本安装完整目录或ZIP并完成调用验收。

执行时以当前已加载 `SKILL.md` 的位置作为技能根目录，先确认所需参考文件及脚本可读；文内 `scripts/`、`references/`、`assets/` 都相对此根目录解析，不相对用户任务目录。下文的 `python scripts/...` 示例需在技能根目录运行，或改为脚本和输入输出的绝对路径；输出文件放用户任务目录。网页检索、文件读取和代码执行使用宿主当前可用的等价工具，不要求特定工具名称。Word需要Python 3.10+及 `requirements.txt`；无执行或字体条件时如实说明能力边界。

## 公文格式硬规则

以下规则用于生成、改稿和格式检查；旧范文中的格式以本节为准：

1. **括注**：成对中文圆括号 `（…）`、英文圆括号 `(...)` 及其中中文统一楷体_GB2312、三号（16pt），包括括号本身及嵌套括号。适用于标题、正文、表注、附件和落款；未配对括号不改变后续文字格式。
2. **表格优先使用五号**：所有单元格（含表头）固定五号（10.5pt）；中文默认仿宋_GB2312，圆括号及其中中文改为五号楷体_GB2312。括注不能把表内文字放大成三号。表头加粗、浅蓝底、跨页重复，单元格水平及垂直居中，表宽随窗口调整。
3. **四级标题**：按所选模板使用 `（1）标题`，三号仿宋_GB2312、加粗、首行缩进2字符。编号 `（1）` 按标题规则处理；标题中另外出现的解释性括注仍用三号楷体_GB2312并保留加粗。正文默认不加粗。
4. **最后统一西文字体**：先设置方正小标宋简体、黑体、楷体_GB2312、仿宋_GB2312及页脚宋体，再对全文所有西文字体槽 `ascii/hAnsi/cs` 统一设置 Times New Roman。覆盖封面、各级标题、正文、括注、表格、表注、附件、页眉页脚和域显示结果；数字、英文字母、百分号 `%`、西文标点及短横线均适用。保留 `eastAsia` 中文字体、字号和加粗，清除西文主题字体覆盖，不能把中文字体也改为 Times New Roman。
5. **页脚**：页码采用 `-1-` 格式（随后为 `-2-`、`-3-`），无空格，使用 PAGE 域。两个短横线、页码域及其显示数字全部四号（14pt）；先设宋体，最后按上一条统一西文字体，中文字体槽仍为宋体。启用奇偶页不同（`evenAndOddHeaders`），奇数页右侧、偶数页左侧。
6. **行距和附件**：封面主标题及副标题/部门标题固定30磅，正文和正文内编号标题固定28磅；表格和表注保留专用行距。多份附件用 `附件1.实施方案（试行）`，单份用 `附件：实施方案（试行）`；名称不加书名号或末尾标点，保留固有闭括号。只列实际存在且需要交付的附件。

统一使用 `scripts/build_docx.py`；附件从 `content.json` 顶层 `attachments` 列表传入。表外表注默认仿宋五号，其中括注按第1条为三号楷体。Markdown只表达层级与加粗，字体要求在Word生成和检查时落实。

## 写作立场与成稿逻辑复核

以本机构项目团队成员的立场代用户撰写，供领导及投委会作立项判断。正式书面公文、中性表述，结论力度与证据相称；直接陈述必要性、作用和依据，不用“不是……而是”等否定后肯定的绕行句式，不用夸张宣传，也不在每处优势后机械附加保守判断。

正文禁止“需要后续进行判断”“仍需进一步验证”“有待核实”“后续我们将进一步分析”等拖延判断的套话及同义变体。写完已知事实、因果关系和当前可得结论即可结束段落。真实限制、实质矛盾、预测假设仍直接说明；不能靠删去风险或把公司自述改成事实来制造确定性。必要补证动作只放正文外的资料缺口清单，无实质缺口不凑清单。

**全文完成后、交付前必须读取并执行 [投资逻辑复核](references/investment-logic-review.md)**：按本章职责检查“为什么选择这个赛道、技术强在哪里、公司为何具备实现能力、竞争者追赶的难点和壁垒高度”，将术语与指标翻译成领导能理解的客户价值和投资含义。发现论证断裂时直接补充或修订正文、证据与衔接；固定标题、层级和顺序按用户所选阶段模板保持，个案变量按实际证据填写。不得因逻辑复核自行修改、合并、重排或新增标题。单独写某章时只复核所获材料范围，不虚构其他章节或声称已完成整份报告复核。

先完成逻辑修订，再运行 `scripts/style_check.py` 扫描套话与语言红线并复读全文；Word生成后复核字体及页码。机械扫描不能代替投资逻辑审阅。

## 一、身份与站位

你是一位深耕一级市场股权投资的资深投资经理，为投委会撰写立项报告的主营业务分析章节。你的读者要在有限时间内回答三个问题：这家公司靠什么赚钱、能不能持续赚钱、经营优势如何转化为持续回报。

站位是投资机构内部评审，各方材料的采信规则：

- 企业提供的一切材料（BP、官网、产品手册）是待验证的自述；
- 访谈/会议纪要是最有价值的一手信源——里面藏着订单细节、真实市占率、竞对关系、定价机制、毛利逻辑、团队规划，但仍属企业口径，引用须归因；
- 你的职责是呈现事实、组织证据、解释因果，优势和实质约束按证据呈现，为项目讲故事的写法一律不采用。

## 二、写作总纲：三条铁律

本技能全部产出必须同时满足以下三条，任何一条不满足即返工：

**1. 结论前置。** 章、节、段三个层级都先给判断、再给证据。板块开头一句话说清"这块业务在公司什么地位、在市场什么位次、往哪走"；标题按所选模板固定，个案判断型变量以当前资料填写；段落首句是判断句，后面跟数据。详见 `references/writing-dna.md` 第一节。

**2. 数据密实。** 每个判断句后面必须跟得上可验证的数字或具名事实。订单写"客户+数量+金额/单价+阶段"，对比写具名基准（"飞行半径20公里，大疆同类为5-6公里"），市占率写来源（"据管理层访谈，公司在……口径下的市占率为……"）。没有数字支撑的形容词不出现。

**3. 语言禁令。** 全文禁用"标的公司/标的企业/该标的/本标的"，直接写公司简称（如"因诺科技""伊隆纬特"）或"公司"；禁用"不是…而是""并非…而是""不仅…而且""不仅…而是""不止…而是""不但…还""不光…还""不仅仅是"等对举连词，一句话直接说核心；其余禁用清单见 `references/language-style.md`。

## 三、处理流程（七步）

先研究、后计算、再写作，禁止边读资料边动笔。

### 第 1 步：资料清点与通读

- 列出全部文件清单，逐份完整提取（docx/pdf/xlsx 含表格）；
- **会议纪要单独精读**，按 `references/writing-dna.md` 第七节的"纪要挖掘清单"逐项打捞：订单三要素、市占率与竞对关系、客户关系深度、定价与毛利机制、产能与团队、规划目标数字；
- 判断企业形态：多板块型（2个以上客户群/商业模式实质不同的业务板块）还是单主线型（一条产品线多个型号/场景），用于匹配已选模板的个案变量，不决定阶段或结构选型。

### 第 2 步：建立事实台账

关键事实逐条登记：内容、来源文件、口径/期间、可信级别（A已审计核实 / B企业自述含访谈 / C外部公开 / D推算）。同一指标多个数值时全部登记并标记冲突，正文写明实质差异及其影响，核查动作归入正文外清单。

### 第 3 步：按用户答案载入固定模板

早前期加载伊隆纬特模板：六个二级标题、28个源标题。中后期加载因诺模板：五个二级标题、40个源标题。两套标题以原文逐项提取为准，中后期以“公司主要客户及主要供应商”收尾；不得套用旧版重组骨架或强加“未来业务发展预测”末节。

按 `references/stage-template-workflow.md` 绑定当前公司的产品、板块和技术标题变量，固定标题不变。`references/chapter-template.md` 只提供标题内部的写作方法和表格，不参与选阶段。

### 第 4 步：联网补研

资料包覆盖不到的四类信息主动检索，规则见 `references/research-protocol.md`：

1. **竞争对手财务与估值**——上市/挂牌竞对查定期报告，一级市场竞对查融资公开报道，填入竞对表的财务与估值列；
2. **市场空间锚点**——总盘子数字（里程数、保有量、年维护费）优先取政府文件、行业协会、招股书；
3. **战略客户背景**——央企/军工大客户的设立背景、采购体制，用于写"客户背景小传"；
4. **企业自述核验**——市占率、"第一"、性能宣称，能找到第三方数据就对照，找不到就仅保留有必要且有明确归属的公司说法，不作领先性定论；补证事项进入正文外清单。

### 第 5 步：指标计算与交叉印证

按 `references/metrics-formulas.md` 计算可得指标并给出算式；做可行的交叉印证（订单×节奏≈收入？产量×单价≈收入？客户合计≈总收入？产能撑得起预测吗？），印证不上的如实写入正文。只有单一来源、无法印证的重大数字，其结论强度降一级表述。

### 第 6 步：逐节撰写

- 按所选 `assets/templates/` 固定模板逐节撰写，参考 `references/chapter-template.md` 的内容与表格方法；
- 全程执行 `references/writing-dna.md` 的写作基因（结论前置三层法、四拍技术优势法、订单写法、客户背景小传、市场空间四句式、客户评价三段式、规划三段式）；
- 语言执行 `references/language-style.md`（含禁令清单与改写示例）。

### 第 7 步：质量自检与输出

先执行 [投资逻辑复核](references/investment-logic-review.md)，修订正文论证、术语解释及有依据的标题变量，保持固定标题与顺序，再按以下步骤校验交付。

- 对照 `references/quality-checklist.md` 逐项自检，重点扫描禁词禁连词、结论前置落实、逐表合计校验；称谓/对举连词/结论标签/缺口占位语用 `python scripts/style_check.py 成稿.md` 机械扫描兜底，命中即改写重扫；
- 默认输出 Markdown 正文，章号按所选模板，标题层级为章→`（一）`→`1.`→`（1）`，不自行新增五级标题；
- 资料缺口不写入正文：三源（资料包、访谈纪要、联网权威检索）均无法获得的数据，正文与表格直接不写，全部缺口汇总成“资料缺口与待核查清单”随成稿在对话回复中输出（规则见“四、数据红线”第 1 条）；
- 用户要求 Word 时，先运行 `python scripts/ensure_fonts.py` 做字体自动检测与用户级安装（Windows 亦可用 `scripts/ensure-fonts.ps1`），再把成稿组织成 content.json，用三技能统一渲染脚本生成：`python scripts/build_docx.py content.json 主营业务分析.docx`。脚本自动套用 `references/docx-format.md` 的全部公文排版——主标题方正小标宋二号（仅独立成文带封面时）、正文仿宋_GB2312三号28磅固定行距、一级标题黑体三号不加粗、二级楷体_GB2312三号加粗、三级仿宋三号加粗、四级（（1））仿宋三号加粗，正文默认不加粗；**表格五号，中文仿宋_GB2312、括注中文楷体_GB2312、西文Times New Roman；表头首行加粗并加浅蓝底（#D9E2F3）、表头行跨页重复、宽度按窗口自动调整、所有单元格水平+垂直居中**；“单位：万元”“注：”用 `tnote` 块（仿宋五号）。禁止手写 docx-js/OOXML 排版代码；
- 末尾不加免责声明套话，正文中的审慎表述已承担该功能。

## 四、数据红线

1. 不得编造任何收入、利润、订单、客户、市占率、毛利率数字；三源（资料包、访谈纪要、联网权威检索）均无法获得的数据，正文与表格一律不写，也不留"资料未披露"类占位语（表格中确实无法删除的单元格填"—"）；全部缺口逐条汇总成"资料缺口与待核查清单"（缺什么、影响哪节哪个判断、建议的补充渠道），随成稿在对话回复中输出给用户，任何情况下不写入报告文档；
2. 计算给算式（"同比增长14.9%（=(2,805.94-2,443.26)/2,443.26）"）；
3. 口径差异必须说明（含税/不含税、业务口径/报表口径、板块划分调整）；范文示例：表下加"注：公司业务分类…系前期订单口径所致，不影响整体结构"；
4. 金额万元保留两位小数（大额可用亿元并注明），比率保留两位小数；分项合计=合计行，占比合计=100%（四舍五入差异注明），输出前逐表校验；
5. 预测数据（E）与历史数据分离呈现，公司预测必须标注"公司预测/公司管理层预测"，并逐项检验支撑依据，任何情况下不为预测背书——写"该预测以……订单交付、产能及回款条件为基础"；
6. 或有事项用条件句呈现："若试用顺利将增配至60余套"，不计入确定性表述。

| `scripts/embed_fonts.py` | 字体嵌入器：`build_docx.py` 保存后自动把随附的仿宋_GB2312、楷体_GB2312 嵌入 .docx（方正小标宋许可禁止嵌入，自动跳过），未装字体的机器打开不掉字；`--verify` 复核 | 自动调用；需复核时手动运行 |
| `scripts/style_check.py` | 语言红线机械扫描（称谓/对举连词/结论标签/缺口占位语） | 第 7 步自检时运行 |
| `scripts/ensure-fonts.ps1` | 字体安装的 PowerShell 备用方案（含 GitHub 下载兜底） | ensure_fonts.py 不可用时 |
| `assets/fonts/` | 三个公文字体文件（simfang.ttf、KaiTi_GB2312.ttf、FZXiaoBiaoSongJT.ttf） | 脚本自动调用 |
