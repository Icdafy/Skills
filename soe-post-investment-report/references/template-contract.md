# 来源派生模板契约

本契约记录从用户提供的投后报告模板及企业公文格式参考中提炼出的可复用版式和结构。企业专属事实、签名、电话号码和字体二进制不属于本契约。

## 两种报告形式

规格以 `document.report_form` 声明报告形式，缺省为 `文件式`：

| 形式 | 来源 | 首部 | 正文固定标题 | 尾部 |
| --- | --- | --- | --- | --- |
| `文件式` | 原控股公司年度报告模板（红头上行文） | 红头、文号／签发人行、两行标题（含发文机关全称）、主送单位、开头依据 | `一、<报告期间>股权投资完成总体情况`、`（一）存续基金`、`（二）新设基金`、`（三）参股公司`、SPV 位置、`二、重大投资项目进展情况` | 附件说明、署名、成文日期、可选联系人，全文最后一页版记 |
| `内部报告式` | 经 16 轮校改定稿通过的半年度报告 | 两行标题（不含单位名称）、其下居中成文年月、空一行、开头段 | `一、项目整体情况`、`（一）参股基金`、`（二）双GP基金`、`（三）参股公司`、SPV 位置、`二、项目台账` | 附件说明；无署名、成文日期行和版记 |

**报告形式沿用上一期定稿。** 用户上传的上一期报告是哪种形式，本期就按哪种形式生成；不得因本技能缺省值而把已定稿的内部报告式退回文件式。

基础模板与本期形式不同时（如上年为文件式、本期改为内部报告式），在 `document.source_report_form` 写明基础模板的形式，`source_fixed_main_headings` 按该形式填写；校验器把形式切换视为固定标题变更，要求 `heading_change_authorized` 为 `true`，并在 `heading_change_note` 逐项写明新旧标题。

## 内部报告式契约

文档组成与顺序：

1. 大标题，二号方正小标宋简体，居中，固定行距 30 磅，同一段落内两行：`关于<标题期间措辞>股权投资项目` ／ `投后管理情况的报告`；
2. 成文年月 `YYYY年M月`，取自 `document.issue_date`，三号楷体_GB2312，居中，固定行距 30 磅，紧接标题下一段；
3. 空一行；
4. 开头段（`document.legal_basis`），写目的、依据、报告期间，并声明“本报告财务数据截至……，重大事项进展更新至……”；
5. `一、项目整体情况` 及其下固定二级标题和 SPV 位置；
6. `二、项目台账`：先一段引导句（如“截至YYYY年M月D日，我司股权投资项目台账如下：”），再一张台账表，可加表注说明收益率口径；
7. 附件说明；
8. 编号附件，每个附件另起一页。

`document.report_form = "内部报告式"` 时：

- 必填：`company`、`report_year`、`report_period`、`cutoff_date`、`legal_basis`、`issue_date`、`heading_contract_source`、`heading_change_note` 及两份固定标题列表；
- 禁填：`document_number`、`signer`、`recipient`、`issuer`、`contact_name`、`contact_phone`、`printer`、`print_date`——这些部件不出现在内部报告式中，校验器阻断而非静默丢弃；
- 项目名册 `category` 取 `参股基金`、`双GP基金`、`参股公司` 或 `SPV项目`；
- `二、项目台账` 下必须有台账表，且表前有引导句；
- 正文页数正常目标为 5—7 页（含台账），硬性上限仍为 10 页；
- 其余字体字号、页面几何、页码、表格、附件格式与文件式相同。

## 文件式文档组成

文件式来源报告由较短的正文和独立编排的附件构成，复用顺序如下：

1. 红色发文机关标志（`<发文机关全称>文件`）；
2. 发文字号与签发人行，下设红色分隔线；
3. 两行报告标题；
4. 主送单位及一段依据或开头；
5. 年度股权投资总体情况；
6. 重大投资项目进展；
7. 附件说明；
8. 发文机关署名、成文日期和可选联系人；
9. 编号项目附件；
10. 版记（印发机关和印发日期），位于全文最后一页。

来源报告把 1—2 项与 5—8 项排在正文，9—10 项另页编排。正常目标为 5—6 页，10 页为硬性上限，附件页数另计。

来源模板中，红头与发文字号／签发人行由一个单列表格承载，仅保留红色（FF0000）下边框；版记由一个单行表格承载，保留上下横线。生成器沿用同一结构，因此校验器按“单行两列表格”定位这两处。

## 正文固定逻辑（文件式；内部报告式的对应标题见上文）

以下一级标题必须逐字保留，现行校验器不支持变更：

- `一、<报告期间>股权投资完成总体情况`——期间措辞取 `document.report_period` 的取值本身（`年度`／`上半年`／`下半年`／`第一至第四季度`），其余部分逐字固定
- `二、重大投资项目进展情况`

第一部分必须保留下列二级标题，顺序不变：

- `（一）存续基金`
- `（二）新设基金`
- `（三）参股公司`
- 一个或多个 SPV 固定位置，自 `（四）` 起连续编号，每个位置写作 `（四）SPV项目` 或 `（四）<项目名称>SPV项目`

SPV 是**可重复位置**，不是单一位置：来源报告按 SPV 项目分设位置，实际含两个具名位置，形如 `（四）甲银行SPV项目` 与 `（五）乙股份SPV项目`；真实项目名称属于来源事实，只出现在用户当前工作副本中，不写入本公开契约。契约允许 1 至 7 个 SPV 位置（`（四）` 至 `（十）`），序号必须连续、不得跳号，因此 `document.fixed_main_headings` 的长度为 6 至 12 项。

将来源准确序列写入 `document.source_fixed_main_headings`，将输出序列写入 `document.fixed_main_headings`。`document.heading_contract_source` 必须非空，用于说明所检查的基础模板，但校验器不会自动核实该记录与原件是否一致。`document.heading_change_authorized` 必须是布尔值，`document.heading_change_note` 必须始终非空。

比较来源快照与输出序列时，第一项一级标题的期间措辞不计入差异：它与大标题一样由 `report_period` 机械推导，来源快照取自上一期报告时本就不同，不属于标题变更。除此之外两份列表一致时，授权值必须为 `false`，备注须说明未调整固定标题。只有 SPV 位置可以在用户后续直接回答四项确认并确认项目变化后调整：既可以改写某位置的项目名称，也可以按新增或退出的 SPV 项目增减位置数量；调整后授权值为 `true`，备注逐项写明来源标题与输出标题。前三项二级标题和 `二、重大投资项目进展情况` 全部不可变。不得仅因公开脱敏示例使用通用名称，就把来源模板中的特定项目名称通用化。

每个具名 SPV 位置在项目名册中应有对应记录。SPV 位置多于名册中 `SPV项目` 类别的记录数时，校验器阻断。

某固定类别没有项目时，保留标题并简要说明“本年度无……项目”。类别下可按需要设置项目三级标题。第二个一级部分下的项目二级标题可依据已确认的重大变化调整，但该部分只写重大进展，不重复完整项目名册。若要改变其他固定标题，必须先有意更新规格和校验器；仅有用户授权不能绕过当前契约。

## 页面几何

报告规格的 `layout` 必须记录下列八个数值属性。生成器把这些数值应用于单一生成节，校验器只比较 `doc.sections[0]`。最终规格不得缺少 `layout` 或其中任一属性；上传模板未变化时使用下表数值。辅助脚本不会自动推断或采用任意上传文档的页面几何。

复杂基础 DOCX 可以保留更多节或混合节，但校验器只会提示其存在，不会逐节认证。必须人工检查每个附加节，不得宣称整份文件均通过本契约的几何认证。

| 属性 | 数值 |
| --- | --- |
| 纸张 | A4 纵向，21.0 cm × 29.7 cm |
| 上边距 | 3.7 cm |
| 下边距 | 3.5 cm |
| 左边距 | 2.8 cm |
| 右边距 | 2.6 cm |
| 页眉距 | 1.5 cm |
| 页脚距 | 1.75 cm |
| 大标题及各级编号标题行距 | 固定 30 磅 |
| 正文、附件说明及落款行距 | 固定 28 磅 |
| 正文首行缩进 | 两个中文字符，OOXML 使用 `w:firstLineChars=200`，随所在字号自适应 |

以上字体字号与 yiti-skill 的 `references/format-rules.md`（统一公文格式标准）一致；红头、发文字号／签发人行、表题和版记为本技能特有部件。

附件说明：正文下空一行，左空二字写 `附件：`；单份为 `附件：XXX`，多份为 `附件：1.XXX`，第二份起另起一行写 `2.XXX`，“2.”与“1.”对齐，名称回行悬挂对齐到本条名称首字（按实际字宽计算，关闭中西文自动间距）。落款：附件说明下空两行，署名右空四字，成文日期在署名下居中，落款不单独成页。

不得为了控制页数缩小字号或行距，应压缩语言并把明细移入附件。

红色发文机关标志参数用于精确重现来源 DOCX 的运行属性，而不是名义视觉字号猜测。必须同时保留 68 pt 主字号、加粗、字符宽度压缩和 `fitText` 数值，单改其中一项会造成明显漂移。

来源模板的一级标题通过段落左缩进（`w:ind w:left=630`，约合三号字两字）取得缩进，二级、三级标题使用 `w:firstLineChars=200`。生成器统一采用字符单位首行缩进：对单行标题两者呈现一致，且随字号自适应。若基于原 DOCX 就地编辑，保留原有缩进属性即可，不必改写为字符单位。

附件内部另起标题层级：附件标签（单份 `附件：`，多份 `附件1：`……）为三号仿宋_GB2312顶格，附件标题为二号方正小标宋简体居中（跨行时在同一段落内换行），附件内 `一、` 用三号黑体、`（一）` 用三号楷体_GB2312 加粗、`1.` 用三号仿宋_GB2312 加粗，序号在每个附件内重新起算。来源模板个别附件的 `1.` 级标题误用“仿宋”而非“仿宋_GB2312”、加粗不一致，属于来源缺陷，复用时统一按上表改正。

## 表格

- 表格适应正文版心，跨页时重复表头。
- 使用黑色单线全框线；表头加粗、不加底纹；单元格单倍行距、水平垂直居中；各行不跨页断开；未给 `widths` 时列宽按内容分配。
- 单位单列右对齐说明，或写入表头。
- 日期、单位和口径写入标签，避免数值误读。
- 在可行范围内禁止单行跨页拆分。
- 只有当前上传模板或用户明确要求时才使用横向节；内置校验器不认证横向节的逐节几何。

内置 JSON 生成器只覆盖标准正文和简单纵向表格。若上传模板或附件含图片、合并／嵌套表格、文本框、独立页眉页脚、横向节或其他复杂 Word 部件，应以原 DOCX 为基础局部更新，不得为适配简单规格而重建或扁平化。结构保留不等于语义提取；工具不会自动读取、建立事实关联或核对复杂文本框和图片的可见含义，最终必须逐页人工检查。

## 页码、页眉与分页

- 页眉不设任何文字、域、图片、图形或其他可见内容。
- 页码置于页脚，采用 `-1-`、`-2-` 形式（无空格），两个短横线、PAGE 域及其显示结果均为四号宋体，四个字体槽均为宋体。
- 奇数页页码位于右侧，偶数页页码位于左侧，即始终位于装订后的外侧。来源模板用单一默认页脚内一个 `<wp:align>outside</wp:align>` 浮动文本框实现；生成器改用奇偶页页脚分别对齐，两种做法的可见结果相同。
- 每个附件另起一页。
- 最终正文分页需要由内置校验器认证时，至少保留一个附件，并在其首页设置独立的附件标签（单份 `附件：`，多份 `附件1：`；校验器同时识别不带冒号的 `附件1`）。
- 附件标题与首段实质内容或首个表格保持在同一页。
- 避免标题孤立在页末。
- 不得通过任意手工分页掩盖篇幅失控；只在渲染后确认的语义边界设置分页。

## 报告期间与标题

标题不是固定文本，而是由报告期间生成：文件式为 `<发文机关全称>关于<标题期间措辞>股权投资项目投后情况报告`，内部报告式为 `关于<标题期间措辞>股权投资项目投后管理情况的报告`（于“股权投资项目”后回行）。期间由 `document.report_year` 与 `document.report_period` 共同确定，`report_period` 取值及其唯一合法的数据截止日期如下：

| `report_period` | 标题期间措辞 | 数据截止日期 |
| --- | --- | --- |
| `年度` | `<年>年度` | 12月31日 |
| `上半年` | `<年>年上半年` | 6月30日 |
| `下半年` | `<年>年下半年` | 12月31日 |
| `第一季度` | `<年>年第一季度` | 3月31日 |
| `第二季度` | `<年>年第二季度` | 6月30日 |
| `第三季度` | `<年>年第三季度` | 9月30日 |
| `第四季度` | `<年>年第四季度` | 12月31日 |

6月30日对应 `上半年` 与 `第二季度`，12月31日对应 `年度`、`下半年` 与 `第四季度`，须由用户确认报送口径。截止日期与所选期间的期末不一致时校验器阻断——半年度数据不得冠以年度标题。截止日期不是任何期末时，须先有意扩展契约，不得用期间措辞掩盖口径不符。

主送单位和开头依据中出现的期间措辞（`YYYY年度`、`YYYY年上半年`、`YYYY年第N季度` 等）必须与标题一致。

文件式的第一项一级标题与大标题同步：`一、<报告期间>股权投资完成总体情况`，例如半年报写 `一、上半年股权投资完成总体情况`、三季度报写 `一、第三季度股权投资完成总体情况`。`二、重大投资项目进展情况` 不含期间措辞，保持原文。内部报告式的 `一、项目整体情况` 与 `二、项目台账` 均不含期间措辞，期间只体现在大标题和开头段中。

## 日期勾稽

- `document.cutoff_date`、`document.issue_date`、`document.print_date` 一律使用公文写法 `YYYY年M月D日`。
- 数据截止日期不得晚于成文日期：成文日期之后才产生的数据，在签发时并不存在。
- 印发日期不得早于成文日期。

## 公文用语与标点

以下问题在来源模板中真实出现过，校验器以警告形式逐条提示，须人工判断后改正：

- 以“截止”表示时间点，规范写法为“截至”；“截止”只用于事项终止。
- 数值或西文与其后全角标点之间出现空格，例如 `7.07% ，`。
- 数值与百分号之间出现空格，例如 `12.56 %`。
- 中文语境内混用半角圆括号或半角逗号、分号、冒号。

数字一律按英美通行写法三位分节：整数部分四位及以上自个位起每三位加一个半角西文逗号，小数点用半角点，如 `1,234.56`、`2,350万元`、`1,000,000`，不写 `2350万元`；小数部分不分节；分节逗号不属于“中文语境内混用半角逗号”。年份、日期、时刻、文号（`〔2026〕1号`）、页码、电话、证件号、统一社会信用代码、股票代码、合同/专利编号、型号、版本号等标识性数字不加逗号。此项为阻断规则：`validate_report.py` 对规格中全部渲染文本（发文字号和联系电话除外）扫描未分节数字；分句校验按分节规则识别逗号，`2,350万元` 不会被拆成两个分句。

法定名称本身含半角符号时保留原样，并在处理记录中说明。

## 由来源异常转化的质量规则

来源模板正文中出现过重复的项目类别标题，该异常不属于复用框架。除非同名标题分别位于不同附件范围且有意区分，否则完全相同或规范化后相同的标题必须导致校验失败。

来源模板还出现过把整段附件内容装入单个 1×1 表格的粘贴痕迹。复用时应还原为正常段落与表格结构，不得原样保留这种包裹。

## 字体许可与可移植性

生成器只把字体族名称写入 DOCX，不打包或嵌入字体二进制。最终出文机器必须安装合法授权的准确字体。字体替换不符合当前字体契约，不能通过记录说明或临时授权将其变成认证成品。可选择安装准确的授权字体、交付明确标注的未认证草稿，或先有意扩展校验契约再交付。
