# 所属行业分析（hangye-fenxi）

当前分发版本：**1.0.1**；变更见 [CHANGELOG.md](CHANGELOG.md)。

## 用途与边界

所属行业、产业链、规模、国产化、壁垒及行业投资判断；不整理工商团队或公司主营业务。

## 输入和输出

输入：行业范围、项目资料、研报、统计来源和项目阶段。

输出：行业分析正文、表格、来源及 DOCX。

## 依赖与字体

Python 3.10+；安装和完整性检查使用标准库，DOCX 生成需 `requirements.txt` 中的 python-docx。

单技能ZIP和安装器输出不含字体。GitHub源码按维护者要求保留原main三份字体，见 [字体说明](assets/fonts/README.md)；其公开再分发授权仍未确认。自行准备有使用权的仿宋、楷体_GB2312、方正小标宋等原版式字体，可用 `ICDAFY_FONT_DIR` 指向授权文件目录；运行 `python scripts/ensure_fonts.py --check` 检测。缺字体须明确说明，不能把草稿称为已通过实际版式验收；原字体、字号和版式规则保留。

## 原业务说明与历史记录

# hangye-fenxi · 立项报告行业分析技能

## 两阶段固定模板

调用写作时先询问“早前期（2026-09 终稿范式）还是中后期（因诺科技）”，用户回答后按对应标题逐项填入当前公司资料。同项目连续调用复用明确答案。完整标题见 [早前期](references/template-early.md)、[中后期](references/template-mid-late.md)；执行与校验见 [阶段模板规则](references/stage-template-workflow.md)。旧版自动选型和标题自由调整已取消。

`hangye-fenxi` 是一款用于撰写、改写与质检**一级市场股权投资立项报告"二、所属行业分析"章节**的 Claude 技能。它以两篇成熟立项报告范文为基准，产出"结论前置、证据解释、产业链收束"的公文式行业分析正文、配套表格，并可生成符合公文版式的 `.docx`（检测本机授权公文字体并提示缺失）。

> 技能名保留英文 `hangye-fenxi` 以稳定调用；界面展示名由 `agents/openai.yaml` 设为中文"立项报告行业分析"。

## 一、能做什么

面向投资机构内部投委会，围绕拟投资公司所处行业，回答四个核心问题：

1. **行业盘子是否足够** —— 市场规模、增速、所处生命周期阶段；
2. **增长是否真实** —— 政策驱动、市场驱动、技术/成本/供给驱动的作用机制；
3. **钱和壁垒集中在产业链哪个环节** —— 上中下游拆解、价值沉淀、议价权、壁垒;
4. **公司卡位是否顺着产业链演进方向** —— 公司落位、卡位能否捕获价值。

### 适用场景（触发信号）

- "写一下所属行业分析 / 二、所属行业分析"；
- "梳理行业发展现状、市场规模与增长趋势"；
- "拆解政策驱动、市场驱动等核心增长动力"；
- "分析产业链上中下游 / 产业链概况 / 产业链图谱"；
- "写一下产业链分析 / 价值链分析"（含各环节价值占比、成本结构、国产化率、竞争格局标签、标的卡哪一环的定量深挖，见 `references/08-chanlian-deep-dive.md`）；
- "提炼产业链洞察与公司卡位启示"；
- 改写或质检既有"行业分析"章节、贴近范文优化。

适用赛道：低空经济、硬科技、半导体、先进制造、卫星通信、机器人、新能源、服务业等一级市场拟投资企业的行业/赛道分析。

### 不适用场景

整份立项报告、公司情况、主营业务分析、财务分析、商业计划书、招股书、二级市场研报。产业链分析（含深度价值占比/国产化率/竞争格局拆解）已并入本技能第 7 步，无需独立技能。

## 二、输入要求

**最低输入只需两类信息：**

1. 公司所处行业或细分赛道；
2. 公司在产业链的环节（上游 / 中游 / 下游 / 上中下游一体 / 侧重某环节）。

若提供 BP、资料包、尽调材料、访谈或财务数据，**仅用于判断公司叫什么、做什么、卖给谁**，据此独立识别行业与产业链位置。行业发展现状、市场规模、政策、产业链结构、竞争格局一律基于**权威公开资料**（政府文件、行业协会、统计分类、招股书、年报、券商研报）独立成文，正文不得出现"根据资料包""据会议纪要"等来源表述。

## 三、输出结构

行业章按用户选择的阶段模板输出：早前期为第二章，中后期为第三章。完整四级标题见上方两份原文对照。

## 四、核心方法论

### 产业链五步法（第 2 步的核心）

1. **识别公司** —— 名称、核心产品/服务、客户；
2. **判断行业与环节** —— 上游（材料/芯片/传感器/算法/零部件/底层软件/检测认证）、中游（整机/系统集成/平台/解决方案/工程交付）、下游（行业应用/运营服务/场景数据/渠道/运维）；
3. **还原产业链全景并拆分细分赛道** —— 赛道数量不预设，由分工与价值分布决定；拆分三准则：口径互斥且合起来覆盖全貌、赛道内格局同质而赛道间有别、价值密集处深拆价值稀薄处粗写；与公司无关的赛道也要完整覆盖；
4. **逐赛道写透** —— 名称、构成、功能、格局定性（垄断/寡头/分散/培育）、代表企业、价值或壁垒信号（成本占比、国产化率、上市率、认证周期）；
5. **落位** —— 公司简称写进所属赛道、与同赛道企业并列，定位由全景衬托；多环节时判断收入与核心壁垒主要落在哪一环，不写"全产业链布局"。

### 语言与排版硬规则

- **标题全部首行缩进 2 个中文字符**，与正文平齐，不顶格、不居中；
- **核心结论直接写成加粗判断句**，不加"核心结论：""核心观点："标签；加粗句连读应构成全篇论点摘要；
- **禁用成对转折/递进连词**："不是……而是""并非……而是""不仅……而且""不但……还"等一律不用，判断句正面直陈；
- **数字加千位分隔符**：整数部分四位及以上每三位加半角逗号（"2,350万元""1,234.56"），年份、文号、编号等标识性数字除外；
- **公司称谓只用简称**（如"因诺科技"），杜绝"标的公司""标的""目标公司"等词；
- 政策驱动写层级、治理逻辑、工具落地与对行业的具体作用，不写政策清单；
- 市场驱动写客户痛点、付费逻辑、存量替代与增量创造，不写"需求旺盛"；
- 技术路线写旧方案局限、新方案作用、适配场景与放量节奏，不做参数科普；
- 图表须承担明确证据岗位（规模证明/阶段解释/政策佐证/技术对比/产业链定位），不装饰化；
- 不把公司结论写成行业结论，是否投资留给立项报告其他章节。

## 六、公文字体（本机授权字体与缺失检测）

生成 `.docx` 立项报告需要三款公文字体，公开包不包含字体二进制，`assets/fonts/README.md` 说明如何自行准备授权字体；检测/安装脚本为 `scripts/ensure_fonts.py`：

| 文件 | 字体 | 公文用途 |
|---|---|---|
| `simfang.ttf` | 仿宋 / 仿宋_GB2312 | 三级及以下标题、正文、核心结论（16pt） |
| `方正小标宋简体.ttf` | 方正小标宋简体 | 公文大标题 |
| `楷体_GB2312.ttf` | 楷体_GB2312 | "（一）（二）"层级标题（16pt 加粗） |

### 使用方法

```bash
# 自行准备授权文件并设置 ICDAFY_FONT_DIR 后，检测并按需做用户级安装
python scripts/ensure_fonts.py

# 仅检测缺失、不安装（缺失时退出码为 1）
python scripts/ensure_fonts.py --check
```

脚本行为：
- Windows 读 HKLM/HKCU 字体注册表按族名判断三款字体是否已装；macOS / Linux 扫描字体目录；
- 缺失时仅从用户自行准备的 `ICDAFY_FONT_DIR` 授权目录安装到**用户级**字体目录（Windows 同时写入 HKCU 字体注册表，Word 才能识别），**无需管理员权限**；
- 已装则直接跳过；跨平台（Windows / macOS / Linux）自适应安装路径。

> **版权声明**：原版式所需字体为受版权保护的商用/系统字体。公开源码与ZIP不包含字体二进制，用户自行确认本机使用和嵌入许可；不得将受限字体带回公开分发。字体名称和版式规范保留。

## 七、DOCX 版式基准

两篇范文的版式规律已固化进技能：

| 项 | 基准 |
|---|---|
| 页面 | A4 纵向 |
| 页边距 | 上 3.7cm、下 3.5cm、左 2.8cm、右 2.6cm（集团行文规范，三技能统一） |
| 行距 | 固定 28 磅 |
| 字号 | 正文与标题基准 16pt |
| 缩进 | 正文与全部层级标题首行缩进 2 个中文字符，标题与段落平齐 |
| 字体 | 一级章标题黑体，二级标题楷体_GB2312，正文及三级以下标题仿宋_GB2312 |
| 页码 | 页脚"-1-"格式，宋体四号，奇偶页外侧 |
| 表格 | 全表统一仿宋_GB2312、五号字（10.5pt），仅首行表头加粗、不加底纹，表头行跨页重复，所有单元格内容水平和垂直居中，宽度按窗口自动调整（autofit），列宽自适应不写死磅值 |
| 加粗 | 二级/三级/四级标题、核心结论、段首论点句、启示总结句加粗；证据句与表格正文默认不加粗 |

## 八、工作流程（九步）

| 步 | 动作 |
|---|---|
| 1 | 内部识别行业边界（狭义赛道/广义行业/客户场景/产业链位置），仅校准口径不作标题 |
| 2 | 从公司业务倒推产业链定位，执行**五步法** |
| 3 | 建立事实台账（规模、增速、政策、环节、代表企业、成本占比、客户场景，逐条记来源/年份/口径） |
| 4 | 用权威公开来源补齐资料缺口，检索不到不编造 |
| 5 | 读 `07-benchmark-lessons.md` + `01-framework.md` 学范文逻辑并组织正文；生成 `.docx` 前读 `02-writing-style.md` 并运行 `ensure_fonts.py` |
| 6 | 写"行业发展现状"（按用户所选阶段的完整固定标题） |
| 7 | 写"产业链分析"（回答投委会五问，两个三级标题） |
| 8 | 读 `04-tables-charts.md` 生成表格与图表建议 |
| 9 | 读 `05-quality-checklist.md` 逐项自检；涉及数字时运行 `reconcile_check.py`；需 `.docx` 时用 `build_docx.py` 渲染 |

### 数据一致性校验

```bash
# 校验市场规模、CAGR、占比、表格的算术与一致性
python scripts/reconcile_check.py 行业分析.md
```

脚本只校验算术和表格一致性；政策力度、产业链卡位、核心结论是否前置需人工核对。

### 生成 .docx

```bash
# 先确保公文字体就位，再把结构化章节内容渲染成 .docx
python scripts/ensure_fonts.py
python scripts/build_docx.py content.json 行业分析.docx
```

`build_docx.py` 自动套用公文版式与表格样式：正文仿宋_GB2312 三号、各级标题按体系设字体并首行缩进 2 字符；表格统一仿宋_GB2312 五号、仅表头加粗、不加底纹、所有单元格水平+垂直居中、宽度按窗口自动调整（autofit）。`content` 用 `blocks` 列表组织，表格作为 `table` 块传入，结构详见脚本头部 docstring。
