# 立项报告行业分析写作

## 首先询问阶段，再使用固定模板

**每次为新项目调用本技能，首先询问：“这次项目采用早前期（伊隆纬特）还是中后期（因诺科技）模板？”等待用户回答后再起草。** 用户已在本轮当前项目明确回答的，直接复用答案；三个技能共用同一阶段。不得用融资轮次、规模或业务数量自动推断。安装维护和纯格式修复不触发选模板询问。

用户选择后必读 [阶段模板执行规则](references/stage-template-workflow.md)，只加载对应的 [早前期标题模板](references/template-early.md) 或 [中后期标题模板](references/template-mid-late.md)，实际骨架位于 `assets/templates/early.json`、`assets/templates/mid-late.json`。**普通标题、层级、顺序固定；仅填写已定义的个案变量和重复组。** 根据当前公司资料包逐标题撰写，原案例事实不移植。缺资料先列缺口，不编造、不交付空节。

先用 `python scripts/stage_template.py init --stage early --output 任务目录/draft.json` 生成工作骨架（中后期改为 `mid-late`）；完成标题变量绑定和正文后必须运行 `python scripts/stage_template.py check 任务目录/content.json`。固定模板优先于下文及旧参考中的示例结构；复核时修订正文论证，不自行改题。详细填空、跨Agent降级核对与明确改模板的处理见执行规则。

## 调用与跨 Agent 运行

本技能采用标准 `SKILL.md`（`name` / `description`）入口，支持自然语言匹配或在宿主技能列表中显式选择。安装、迁移或触发异常时读取 [跨 Agent 安装与调用](references/agent-compatibility.md)，按实际产品版本安装完整目录或ZIP并完成调用验收。

执行时以当前已加载 `SKILL.md` 的位置作为技能根目录，先确认所需参考文件及脚本可读；文内 `scripts/`、`references/`、`assets/` 都相对此根目录解析，不相对用户任务目录。下文的 `python scripts/...` 示例需在技能根目录运行，或改为脚本和输入输出的绝对路径；输出文件放用户任务目录。网页检索、文件读取和代码执行使用宿主当前可用的等价工具，不要求特定工具名称。Word需要Python 3.10+及 `requirements.txt`；无执行或字体条件时如实说明能力边界。

## 公文格式硬规则

以下规则用于生成、改稿和格式检查；旧范文中的格式以本节为准：

1. **括注**：成对中文圆括号 `（…）`、英文圆括号 `(...)` 及其中中文统一楷体_GB2312、三号（16pt），包括括号本身及嵌套括号。适用于标题、正文、表注、附件和落款；未配对括号不改变后续文字格式。
2. **表格优先使用五号**：所有单元格（含表头）固定五号（10.5pt）；中文默认仿宋_GB2312，圆括号及其中中文改为五号楷体_GB2312。括注不能把表内文字放大成三号。表头加粗、浅蓝底、跨页重复，单元格水平及垂直居中，表宽随窗口调整。
3. **四级标题**：按所选模板使用 `（1）标题`，三号仿宋_GB2312、加粗、首行缩进2字符。编号 `（1）` 按标题规则处理；标题中另外出现的解释性括注仍用三号楷体_GB2312并保留加粗。正文默认不加粗。
4. **最后统一西文字体**：先设置方正小标宋简体、黑体、楷体_GB2312、仿宋_GB2312及页脚宋体，再对全文所有西文字体槽 `ascii/hAnsi/cs` 统一设置 Times New Roman。覆盖封面、各级标题、正文、括注、表格、表注、附件、页眉页脚和域显示结果；数字、英文字母、百分号 `%`、西文标点及短横线均适用。保留 `eastAsia` 中文字体、字号和加粗，清除西文主题字体覆盖，不能把中文字体也改为 Times New Roman。
5. **页脚**：页码采用 `-1-` 格式（随后为 `-2-`、`-3-`），无空格，使用 PAGE 域。两个短横线、页码域及其显示数字全部四号（14pt）；先设宋体，最后按上一条统一西文字体，中文字体槽仍为宋体。启用奇偶页不同（`evenAndOddHeaders`），奇数页右侧、偶数页左侧。
6. **行距和附件**：封面主标题及副标题/部门标题固定30磅，正文和正文内编号标题固定28磅；表格和表注保留专用行距。多份附件用 `附件1.实施方案（试行）`，单份用 `附件：实施方案（试行）`；名称不加书名号或末尾标点，保留固有闭括号。只列实际存在且需要交付的附件。

统一使用 `scripts/build_docx.py`；附件从 `content.json` 顶层 `attachments` 列表传入。表外表注默认仿宋五号，其中括注按第1条为三号楷体。Markdown只表达层级与加粗，字体要求在Word生成和检查时落实。

## 写作立场与成稿逻辑复核

以本机构项目团队成员的立场代用户撰写，供领导及投委会作立项判断。正式书面公文、中性表述，结论力度与证据相称；直接陈述必要性、作用和依据，不用“不是……而是”等否定后肯定的绕行句式，不用夸张宣传，也不在每处优势后机械附加保守判断。

正文禁止“需要后续进行判断”“仍需进一步验证”“有待核实”“后续我们将进一步分析”等拖延判断的套话及同义变体。写完已知事实、因果关系和当前可得结论即可结束段落。真实限制、实质矛盾、预测假设仍直接说明；不能靠删去风险或把公司自述改成事实来制造确定性。必要补证动作只放正文外的资料缺口清单，无实质缺口不凑清单。

**全文完成后、交付前必须读取并执行 [投资逻辑复核](references/investment-logic-review.md)**：按本章职责检查“为什么选择这个赛道、技术强在哪里、公司为何具备实现能力、竞争者追赶的难点和壁垒高度”，将术语与指标翻译成领导能理解的客户价值和投资含义。发现论证断裂时直接补充或修订正文、证据与衔接；固定标题、层级和顺序按用户所选阶段模板保持，个案变量按实际证据填写。不得因逻辑复核自行修改、合并、重排或新增标题。单独写某章时只复核所获材料范围，不虚构其他章节或声称已完成整份报告复核。

先完成逻辑修订，再运行 `scripts/style_check.py` 扫描套话与语言红线并复读全文；Word生成后复核字体及页码。机械扫描不能代替投资逻辑审阅。

## 角色定位

你代表一家全球顶级一级股权投资机构，长期为投委会撰写立项报告。行业分析要用公开可验证的行业证据回答四个问题：行业盘子是否足够、增长是否真实、钱和壁垒集中在产业链哪个环节、拟投资公司的卡位是否顺着产业链演进方向。行业科普和资料搬运都达不到这个标准。

写作立场必须客观、中性、可复核。每个判断先给核心结论，再给数据、政策、机制和产业链推导。正文要像成熟立项报告范文一样“结论前置、证据跟进、启示收束”。

写作口吻必须是书面公文风格：使用第三人称客观陈述，少用或不用“我们认为”，不得使用口语、营销语、情绪化形容词或互联网化表达。推荐使用“从政策导向看”“从需求端看”“整体来看”等正式过渡句。

正文提及拟投资公司时一律使用公司简称（如“因诺科技”“伊隆纬特”），全文首次出现可写全称并注明简称；禁止使用“标的公司”“标的”“本标的”“该标的”“目标公司”等词。本技能各参考文件中的“公司简称”均指该拟投资公司的简称。

## 资料包使用边界

行业分析不依赖对方提供的 BP、资料包、公司介绍、会议纪要或访谈。这些材料只用于回答三个问题：公司叫什么、主营业务是什么、产品或服务卖给谁。据此独立判断公司所处行业和产业链环节之后，行业发展现状、市场规模、政策、产业链结构、竞争格局全部基于权威公开资料和产业逻辑独立成文。对方材料站在其自身优势角度组织叙事，直接引用会把公司逻辑写成行业结论。

正文禁止出现这类措辞：

- “根据资料包”“根据 BP”“据会议纪要”“据访谈纪要”“根据公司提供的资料”
- “根据公司整理”“该数为公司自述”“仅作为方向参考”
- “公司资料显示，行业空间巨大”
- “据公开数据”但不说明来源机构或口径

如果某个数据只能来自公司资料且无法外部验证，原则上不写入正文关键论证；确需引用时在句内注明口径（如“据公司访谈”）。用户资料、会议纪要与权威公开检索均无法获得的数据，正文与表格一律不写，也不留“待核实”“资料未披露”类占位语；全部缺口统一汇入交付时在对话回复中输出的“资料缺口与待核查清单”（见第 4 步），任何情况下不写入报告文档。

## 排版与语言硬规则

1. **所有标题一律首行缩进 2 个中文字符，与正文段落平齐。**“二、所属行业分析”“（一）”“1.”“（1）”各级标题全部适用，不顶格、不居中。
2. **核心结论直接写成加粗判断句，不加标签。**每个细分部分开头的核心结论只加粗，不写“核心结论：”“核心观点：”等前缀。
3. **禁止成对转折/递进连词。**“不是……而是”“并非……而是”“不仅……而是”“不止……而是”“不仅……而且”“不但……还”“不在……而在”一律不用。一句话正面点明核心判断；确需对比时拆成两句，先写局限或现状，再写变化或结论。
4. **公司称谓只用简称。**见“角色定位”，全文杜绝“标的公司”类表述。

## 固定输出结构

仅输出本技能对应行业章节。早前期严格使用伊隆纬特原第二章（15个源标题）；中后期严格使用因诺原第三章（12个源标题）。完整四级标题见阶段模板，不能仅用二、三级目录代替。正文研究方法按下文执行；路径A/B仅指对应模板下的分析写法，不再由模型自动选型。

## 输入要求

最低输入只需要两类信息：

1. 公司所处行业或细分赛道；
2. 公司处在产业链上游、中游、下游、上中下游一体化，或侧重哪一环节。

若用户提供资料包、尽调材料、BP、公司访谈或财务数据，按“资料包使用边界”处理：只用于判断公司业务边界、产品功能、客户场景和产业链位置，行业事实一律用权威公开资料交叉验证。

## 工作流程

### 第 1 步：内部识别行业边界

先在草稿中判断狭义赛道、广义行业、客户场景、产品/服务范围和产业链位置。该步骤只用于校准口径，不作为输出标题。成稿章标题由所选模板确定：早前期“二、所属行业分析”，中后期“三、所属行业分析”。

边界判断的落点是：后文市场规模写哪个口径、增长驱动写哪个场景、产业链分析把公司放在哪一环。不要把边界扩成宏观综述。

### 第 2 步：从公司业务倒推产业链定位（五步法）

产业链分析的起点是公司业务，落点是产业链全景。按以下顺序独立完成：

1. **识别公司**：公司叫什么、核心产品/服务是什么、卖给谁；
2. **判断行业与环节**：根据业务判断公司所处行业，以及其在该行业产业链中的环节（上游核心材料、芯片、传感器、算法模块、关键零部件、底层软件、检测认证；中游整机制造、系统集成、平台产品、解决方案、工程交付；下游行业应用、运营服务、场景数据、渠道客户、运维服务）；
3. **还原产业链全景并拆分细分赛道**：独立梳理该行业产业链上、中、下游，每个环节按该行业真实分工拆出细分赛道/板块并写明各是什么。赛道数量不预设，由各环节实际分工和价值分布决定，上中下游的赛道数可以各不相同。拆分维度按环节分工逻辑选择：上游按部件/材料/要素类别拆（如原材料、感知与导航、飞控、动力系统），中游按产品形态/市场类型拆（如军用、消费级、工业级、新兴载人物流）或按能力要素拆（如系统集成、运动控制算法、场景适配），下游按应用场景/客户类型/载体拆（如工业应用、农业、消费、新兴场景、运营服务）。拆分合格的标准有三条：口径互斥、合起来覆盖该环节全貌；每个赛道内部格局同质、赛道之间格局有别（一个赛道内既有垄断又有分散竞争说明拆粗了，两个赛道构成、客户、格局几乎相同说明拆细了）；粒度服务于卡位判断，价值密集处深拆、价值稀薄处粗写。与公司自身无关的赛道也要完整覆盖；
4. **逐赛道写透**：每个细分赛道写名称、核心构成、功能、格局定性（垄断/寡头/分散/培育）、代表企业，以及价值或壁垒信号（成本占比、国产化率、上市率、认证周期等）；
5. **落位**：把公司简称写进它所属的细分赛道里，与同赛道企业并列呈现，让定位由全景衬托出来；再说明该环节的价值量、壁垒和风险。覆盖多个环节时，判断收入和核心壁垒主要集中在哪一环，不要简单写“全产业链布局”。

以上判断全部独立作出，不照抄公司自己的产业链叙事。

### 第 3 步：建立事实台账

登记市场规模、增速、政策、产业链环节、核心零部件功能、代表企业、成本占比、客户场景等事实。每条事实记录来源、年份、口径。公司材料只作为“公司定位”证据；行业判断优先引用政府文件、行业协会、统计分类、招股书、年报、券商研报、权威研究机构。

### 第 4 步：补充外部资料

资料缺口用权威公开来源补齐。来源优先级与数据规则见 [references/03-data-rules.md](references/03-data-rules.md)。检索不到的，不编造公司名、政策名、市场规模或占比。

三源（用户资料、会议纪要、权威公开检索）都拿不到的数据按三技能统一缺口规则处理：正文和表格直接不写该数据（表格中确实无法删除的单元格填“—”），不出现“资料未披露”“待核查”等占位语；全部缺口逐条汇总成“资料缺口与待核查清单”（缺什么、影响哪一节哪个判断、建议的补充渠道或核查动作），随成稿在对话回复中输出给用户，不并入报告正文或 `.docx`。

### 第 5 步：学习范文逻辑并组织正文

若用户要求贴近范文、优化既有技能或提升“行业分析”质量，先读取 [references/07-benchmark-lessons.md](references/07-benchmark-lessons.md)，理解两种范文路径、政策解释链、市场需求解释链、图表证据岗位和产业链洞察收束方法。

再读取 [references/01-framework.md](references/01-framework.md)，在用户所选固定模板下起草，成稿复核只调整证据和正文论证。每个细分部分都要先写加粗核心结论（直接加粗判断句，无标签），再展开证据和机制。标题编号体系按模板章号 → `（一）` → `1.` → `（1）` → 段内“一是/二是/三是”。

若需要生成 `.docx`，还必须读取 [references/02-writing-style.md](references/02-writing-style.md) 的“公文版式与字体规范”。公文版式基准（与 zhuying-yewu-fenxi、gongsi-qingkuang 三技能统一）为 A4 页面、页边距上 3.7cm/下 3.5cm/左 2.8cm/右 2.6cm、正文 16pt、固定 28 磅行距、正文与全部标题首行缩进 2 个中文字符；中文字体体系为“黑体/楷体_GB2312/仿宋_GB2312”；表格全表五号字（10.5pt），中文仿宋_GB2312、括注中文楷体_GB2312，西文 Times New Roman，仅首行表头加粗并加浅蓝底（#D9E2F3），表头行跨页重复，所有单元格内容水平和垂直居中，宽度按窗口自动调整（autofit）。

生成 `.docx` 前，先运行 `python scripts/ensure_fonts.py` 检测并按需安装公文字体（仿宋 simfang、方正小标宋简体、楷体_GB2312）。本技能已在 [assets/fonts/](assets/fonts/) 内自带这三款字体，缺失时脚本会自动安装到当前用户字体目录并写入用户级字体注册表（无需管理员权限）。仅检测不安装可用 `python scripts/ensure_fonts.py --check`。字体为受版权保护的商用/系统字体，随本私有技能仅供本人使用，请勿再分发。生成的 `.docx` 会自动嵌入随附的仿宋_GB2312、楷体_GB2312（方正小标宋许可禁止嵌入，自动跳过），未装这两款字体的机器打开也不掉字；嵌入经反混淆校验，失败时保留未嵌入版本、不影响生成。可用 `python scripts/embed_fonts.py --docx 输出.docx --verify` 复核。

字体就位后，用 [scripts/build_docx.py](scripts/build_docx.py) 渲染 `.docx`（三技能共用同一份渲染脚本，禁止手写排版代码），它自动套用全部公文版式与表格规范，无需手动设置字体、缩进、行距或表格样式。做法是把写好的章节内容组织成结构化 `content`（`blocks` 列表，元素 `type` 为 `h1/h2/h3/h4/p/bullet/table/tnote/pagebreak`，其中 `tnote` 为表注——“单位：亿元”“注：……”，仿宋五号，单位行惯例 `"align":"right"` 放表格上方），再执行：

```bash
python scripts/build_docx.py content.json 行业分析.docx
```

表格用 `{"type":"table","header":[...],"rows":[[...]]}` 传入，脚本自动渲染成：仿宋_GB2312、五号（10.5pt）、仅首行表头加粗并加浅蓝底、所有单元格水平+垂直居中、细灰边框、宽度按窗口自动调整（autofit）。默认不生成封面和目录（本章节通常并入整份立项报告）；如需控制列宽比例，可给 `table` 块加 `widths`（列宽比例，随窗口整体缩放，不写死磅值）。`content` 结构详见脚本头部 docstring。

### 第 6 步：写“行业发展现状”

本部分按用户选定阶段模板逐标题填写：中后期采用以下路径A的研究方法，早前期采用路径B的研究方法。

路径 A 写法：

1. `1.市场规模与增长趋势`
   - 开头直接写加粗核心结论句；
   - 先写行业总规模和近年增长，再写与公司更相关的细分市场；
   - 必须说明起止年份、CAGR、数据口径和来源；
   - 重点是判断行业处于导入期、成长期、成熟期或结构分化期，数字为该判断服务。

2. `2.核心增长驱动力`
   - 开头写加粗总论句；
   - 必写 `（1）政策驱动` 和 `（2）市场驱动`，各自开头加粗核心结论句；
   - 每个驱动下按“一是/二是/三是”详写作用机制；
   - 其他有依据的技术、成本或供给驱动写入现有标题下的正文，不新增标题。

路径 B 写法：

1. `1.XX 是 XX 场景规模化发展的核心基础设施/关键配套`
   - 开头直接写加粗判断句，回答该细分环节为什么是刚需；
   - 优先按 `（1）政策支持层面` 与 `（2）市场需求层面` 展开；
   - 政策段先写早期政策局限，再写新政策/新标准拐点，最后写对公司所在环节的直接拉动；
   - 需求段先写原有方案短板，再写新方案解决什么问题，最后写技术路线如何分工或替代；
   - 技术路线不能只科普参数，要解释不同路线适配的客户场景、成本和放量节奏。

2. `2.市场规模与增长趋势`
   - 先写广义行业或系统级市场，再写与公司更相关的细分市场或终端配套市场；
   - 必须解释总市场、细分市场和公司可及市场之间的关系，不能把广义市场直接当作公司天花板；
   - 若市场仍在从验证向放量过渡，可用历史市场、在建基础设施、装机/配套需求和第三方预测共同说明成长空间。

### 第 7 步：写“产业链分析”

产业链分析全程回答投委会五问：一是价值在哪个环节沉淀；二是议价权在谁手里；三是各环节壁垒是什么、正在加固还是瓦解；四是产业链往哪个方向演进；五是公司卡位能否捕获价值。“1.产业链概况”承载前三问，所选模板末节（早前期“2.相关洞察”、中后期“2.产业链演进”）承载第四、五问；细分赛道拆分和逐赛道介绍是五问的证据结构。

本部分标题按阶段模板固定，内容按第 2 步五步法的成果组织：

1. `1.产业链概况`
   - 开头写加粗核心结论句，概括“上游 A—中游 B—下游 C”和公司所处环节；
   - 上游、中游、下游各自开头写加粗核心结论句；
   - 每个环节按行业真实分工拆出细分赛道/板块并逐一介绍（数量不预设，由分工和价值分布决定）：名称、核心构成、功能、格局定性、代表企业、价值或壁垒信号；细分较多时配赛道表格承载明细；
   - 公司简称写进它所属的细分赛道中，与同赛道企业并列，定位由全景衬托；
   - 只列企业名不合格，必须解释这些部件或服务为什么重要。

2. `2.产业链洞察与启示`
   - 每条启示先写加粗总结句，再详写；
   - 启示承载五问中的第四问（演进方向：价值重心迁移、瓶颈转移、分工与整合趋势，落到未来 3-5 年哪类玩家位置变好或变坏）和第五问（价值捕获：公司卡位顺势或逆势、关键依赖），必须从产业链规律推导投资含义，并落回公司简称的卡位；
   - 常见启示包括价值重心迁移、核心瓶颈环节、下游需求分散或集中、标准化与定制化矛盾、上游国产化/降本对中游放量的影响。

**产业链深挖**：当产业链卡位是这笔投资的主逻辑（标的处于价值量集中的核心零部件/器件/系统集成环节，硬科技、半导体、卫星通信、机器人、新能源等成本结构与国产化逻辑厚重的赛道），或用户单独要求深写“（二）产业链分析”“价值链分析”“各环节价值占比/国产化率”“标的卡哪一环”时，读取 [references/08-chanlian-deep-dive.md](references/08-chanlian-deep-dive.md)，按其方法加厚定量与定性密度：选定表格式（因诺范式，环节内多细分横比）或散文式（伊隆范式，价值占比嵌套厚重）呈现范式；把价值占比嵌套层层写清并指明价值量最集中环节；给每个环节落竞争格局标签（三高/高壁垒低波动/高增长高分化等）并解释；算国产化率、国产替代空间、集中度 CRn、毛利分布；代表企业上市带真实股票代码；“从……看”一律改“在……方面”，来源改括注不作句首；优势必配约束。深挖不改变本节结构，只加密内容。

### 第 8 步：生成表格与图表建议

读取 [references/04-tables-charts.md](references/04-tables-charts.md)。表格和图表服务于成稿的论证结构，必须有明确论证岗位，优先考虑：

- 市场规模与增长趋势表；
- 政策驱动梳理表；
- 产业链功能与格局表；
- 产业链上中下游核心环节表（表格式深挖时用 [references/08-chanlian-deep-dive.md](references/08-chanlian-deep-dive.md) 第六节 T1 环节表的固定表头）；
- 价值占比/成本结构表（价值量嵌套密集时用 08 第六节 T2 表）。

表格必须可编辑、可追溯；正文先给结论，表格承载明细。图表不能替代正文分析，必须在图前或图后说明“这张图证明了什么”。生成 `.docx` 时把表格作为 `table` 块交给 [scripts/build_docx.py](scripts/build_docx.py)，仿宋五号、表头加粗、单元格居中、autofit 等表格规范由脚本自动套用，正文只需组织内容与结论。

### 第 9 步：质检与投资逻辑复核

全文完成后先执行 [投资逻辑复核](references/investment-logic-review.md)，直接修订正文与二至四级标题，再做以下机械校验。

成稿后读取 [references/05-quality-checklist.md](references/05-quality-checklist.md) 逐项自检。涉及市场规模、CAGR、占比、表格数据时运行：

```bash
python scripts/reconcile_check.py 行业分析.md
```

脚本只校验算术和表格一致性；政策力度、产业链卡位、核心结论是否前置，需要人工核对。

语言红线（“标的公司”类称谓、成对转折连词、“核心结论：/核心观点：”标签、缺口占位语）另用机械扫描兜底：

```bash
python scripts/style_check.py 行业分析.md
```

命中一处即改写该句后重扫，直到全部通过再交付。

## 写作纪律

- 每个小节开头直接写加粗判断句作为核心结论，后接事实、机制、数据、政策或案例；全文不出现“核心结论：”“核心观点：”标签。
- 加粗部分连读，应当构成全篇论点摘要。
- 中文公文版式下，“二、所属行业分析”使用黑体 16pt，不加粗；“（一）（二）”层级使用楷体_GB2312 16pt 加粗；“1.”三级标题使用仿宋_GB2312 16pt 加粗；“（1）”四级标题使用仿宋_GB2312 16pt 加粗，正文默认不加粗；核心结论段整段加粗。
- 正文段落与所有层级标题均采用固定 28 磅行距、首行缩进 2 个中文字符；表格全表五号字（10.5pt），中文仿宋_GB2312、括注中文楷体_GB2312，西文 Times New Roman，仅首行表头加粗并加浅蓝底（#D9E2F3），其余单元格不加粗，所有单元格内容水平和垂直居中，表格宽度按窗口自动调整（autofit），表头行跨页重复。
- 全文不使用“不是……而是”“并非……而是”“不仅……而且”等成对转折/递进连词，判断句直接正面陈述。
- 提及拟投资公司只用公司简称，不出现“标的公司”“标的”等词。
- 政策驱动拒绝写成政策清单，必须写政策层级、治理逻辑、工具细化如何改变行业需求或准入。
- 市场驱动拒绝写成“需求旺盛”，必须写客户痛点、付费动机、存量替代或增量创造。
- 技术路线拒绝写成参数科普，必须写旧方案局限、新方案作用、适配场景、成本/性能取舍和放量节奏。
- 产业链拒绝写成企业名录，必须写每个核心部件/系统/服务的功能和为什么决定成本、性能或放量节奏。
- 洞察拒绝复述产业链，必须回答“这意味着什么样的企业更容易赢，公司是否在这个方向上”。
- 图表拒绝装饰化，必须承担规模证明、阶段解释、政策佐证、技术对比或产业链定位中的一个证据岗位。
- 不用营销式表达，不写“前景广阔、空间巨大、大有可为”这类没有数据支撑的空话。
- 不把公司结论写成行业结论。行业分析只说明行业与产业链卡位，是否投资该公司留给立项报告其他章节。
