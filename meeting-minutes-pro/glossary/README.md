# 术语库

两层结构：

- `industry/`：**行业术语库**，固定、可复用，随仓库分发到每台安装本技能的机器（入 Git 仓库）。当前包含 `低空经济.txt`、`商业航天.txt`。
- 本目录根下的 `<项目或公司名>.txt`：**项目术语文件**，按项目或公司沉淀的用户数据，仅保留在本地，不入库、不随技能分发（`.gitignore` 和安装复制均排除）。

两类文件格式相同：UTF-8 纯文本，内容是空格或换行分隔的人名、公司名、产品名、简称和专业术语，可按行分主题组织。**不支持注释行**——校验脚本按空白切词读取，注释文字会被当作术语。

```text
张三 李四 某某科技 XX-3000 智能网联 SaaS ARR
```

## 项目术语文件（本地）

使用规则（见 SKILL.md「前置信息采集」）：

- 转录前检查是否已有同一项目或公司的术语文件，存在即读取并入 `--context`，不再要求用户重复提供；
- 首次调用时主动询问是否有会议笔记、BP、尽调资料或术语表等辅助文件；已有文件时直接复用，未提供时依据会议内容继续处理；
- 辅助文件只针对会议中模糊的人名、公司名、产品名、简称、专业术语或数据定点查阅，不整份提取资料内容，不按 BP 的章节、数字或结论补写纪要；
- 资料可提供规范写法或数据候选；须结合上下文回听或请用户确认，再写入修订稿并在复核清单记录依据。只把本次确认的人名、简称和术语追加进对应文件，供同一项目后续会议复用；
- 数据只用于核对具体模糊片段，不写入术语文件或 ASR `--context`；
- 术语是识别提示而非必然出现的文本，避免堆砌无关词条。

## 行业术语库（随技能分发）

会议涉及低空经济、商业航天等行业时读取对应文件，用法分三处：

- **转录热词**：从库中挑选与本场会议直接相关的少量词条并入 `--context`，不整库传入——热词过长会稀释偏置效果，且 `refine_transcript.py` 的 context 上限为 400 字符；
- **起草与复核**：作为人名、机型、术语的规范写法参照；`fact_check.py --glossary` 可与项目术语文件一并传入（参数可重复），获得术语改写提示；
- **注意**：`refine_transcript.py` 的 `--glossary` 以项目术语文件为主——行业库中的通用词（如"无人机""卫星"）几乎每句都出现，整库传入会把过多片段标为高风险。

术语库和参考文件都是核对工具，不能成为新增会议事实的来源。纪要中不写“参考 BP”“经术语核对”“转录识别为”等加工说明；核对过程保存在修订记录与复核清单中。

行业库词条可直接编辑对应文件扩充并提交仓库；新增其他行业时在 `industry/` 下新建 `<行业名>.txt` 即可。

## 自定义禁词文件（本地，可选）

`banned-phrases.txt`：机构自定义的纪要禁用表述，每行一条短语，`#` 开头为注释行。`quality_check.py` 启动时自动加载并与内置禁用表述同等拦截（同样通过 `--allow-line` 放行转录稿真实谈及的内容）。该文件与项目术语文件一样仅存本地，不随技能分发。

```text
# 示例：宣传腔与机构红线词
赋能
形成闭环
```

本目录下除本说明和 `industry/` 外的文件属于用户数据，发布或分发技能时不应包含。新版安装器默认不复制源私有数据；`--force` 更新保留目标私有数据，不删除整个技能目录。手工压缩目录不会自动遵循 `.gitignore`，应按上述边界排除。
