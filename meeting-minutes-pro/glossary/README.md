# 术语库

工作流按精确项目名自动发现词库时，同名 JSON 优先并取代 TXT；迁移前应把原 TXT 全部已确认词条完整保留到 JSON。原 TXT 可留作备份，新增候选应写入已有完整 JSON，不能仅创建一个候选 JSON 而遮住原词表。显式 `--glossary` 可选择具体文件；不要同时把旧 TXT 与含纠正状态的新 JSON 当作两个独立事实源。

两层结构：

- `industry/`：**行业术语库**，固定、可复用，随仓库分发到每台安装本技能的机器（入 Git 仓库）。当前包含 `低空经济.txt`、`商业航天.txt`。
- 本目录根下的 `<项目或公司名>.txt` 或 `.json`：**项目术语文件**，按项目或公司沉淀的用户数据，仅保留在本地，不入库、不随技能分发（`.gitignore` 和安装复制均排除）。

已有 TXT 文件继续可用：UTF-8 纯文本，内容是空格或换行分隔的人名、公司名、产品名、简称和专业术语，可按行分主题组织。**支持整行注释**：忽略行首空白后以 `#` 开头的整行，以及空行；生成 ASR `--context` 时也只选取有效词条，不带入注释。注释须独占一行，不支持行尾注释，词条内部的 `#`（如 `C#`）保留。兼容旧行为，TXT 词条视为此前已确认，单字符词仍被过滤；这不代表脚本重新核实过词条。

```text
张三 李四 某某科技 XX-3000 智能网联 SaaS ARR
```

## 结构化词条（可选）

需要保留 `Full Mask` 等含空格短语、区分别名与错写词、记录确认依据时使用 JSON。不自动迁移或改写现有私有 TXT：

```json
{
  "schema_version": 1,
  "entries": [
    {
      "term": "Full Mask",
      "aliases": ["全掩膜"],
      "misrecognitions": ["富尔马斯克"],
      "category": "技术",
      "project": "项目甲",
      "status": "candidate",
      "source": "本场音频与辅助材料中的待核对候选",
      "confirmed_at": "",
      "priority": 10
    }
  ]
}
```

`term` 必填，其他词条字段可省略。`status` 只能为 `candidate` 或 `confirmed`，省略时是 `candidate`；候选词及其别名不进入 ASR 提示。实际核对后才改为 `confirmed`，填写依据和确认日期，不能仅凭 ASR 输出自动晋升。`aliases` 只放确属同一对象的有效写法；`misrecognitions` 只放已有依据的误识别写法，仅用于定位需复核片段，不作为热词或自动替换规则。`priority` 是同类词条内的整数排序值，越大越优先。JSON 不支持注释，未知字段或非法格式会明确报错。

## 准备与检查热词

`scripts/glossary.py` 提供统一读取和选词；只处理显式提供的文件，不扫描并拼接所有行业库。实际任务先选相关项目、行业及本场词条，必要时将少量相关行业词写入本场临时词表，再传给运行入口。

```powershell
<runtime-python> <skill-dir>/scripts/glossary.py --glossary <项目词库.json> --context "本场优先人名 产品型号" --project "项目甲" --engine qwen --limit 400 --output <job-dir>/context-manifest.json
```

输出包含最终 `context`、选中词 `terms`、带来源的 `selected`、未选中词及原因 `dropped`、输入文件哈希与 `adapter_notes`。显式 context 或 `--term` 优先，其次项目词，最后是调用者选定的行业词；相同词去重，在完整词条边界内遵守字符预算，不截断词条。与当前项目明确不符的结构化词条会排除并记录原因；显式本场词视为本次提供的提示，不因词库项目标记而被过滤。显式 context 延续空白分词方式，含空格短语应写入 JSON 或通过 `--term "Full Mask"` 传入。

400 字符是调用者可配置的默认提示预算，不是对模型能力上限的断言。Qwen 收到保留短语的文本上下文；FunASR 当前默认 SeacoParaformer 的字符串 `hotword` 接口仍按空白分词，因此清单会提示含空格短语的适配限制，不能据此声称模型已将短语作为单个热词使用。热词效果应通过真实录音的对照转录验证，选中或两模型一致不等于说法真实。

## 项目术语文件（本地）

使用规则（见 SKILL.md「前置信息采集」）：

- 转录前检查是否已有同一项目或公司的术语文件，存在即读取并入 `--context`，不再要求用户重复提供；
- 首次调用时主动询问是否有会议笔记、BP、尽调资料或术语表等辅助文件；已有文件时直接复用，未提供时依据会议内容继续处理；
- 辅助文件只针对会议中模糊的人名、公司名、产品名、简称、专业术语或数据定点查阅，不整份提取资料内容，不按 BP 的章节、数字或结论补写纪要；
- 资料可提供规范写法或数据候选；须结合上下文回听或请用户确认，再写入修订稿并在复核清单记录依据。只把本次确认的人名、简称和术语追加进对应文件，供同一项目后续会议复用；
- 数据只用于核对具体模糊片段，不写入术语文件或 ASR `--context`；
- 术语是识别提示而非必然出现的文本，避免堆砌无关词条。

## 行业术语库（随技能分发）

会议涉及低空经济、商业航天等行业时读取对应文件，用法分三处：

- **转录热词**：从库中挑选与本场会议直接相关的少量词条，不整库传入；统一选词器按完整词条控制预算，超预算或未确认词的排除原因保存在清单中；
- **起草与复核**：作为人名、机型、术语的规范写法参照；`fact_check.py --glossary` 可与项目术语文件一并传入（参数可重复），获得术语改写提示；
- **注意**：`refine_transcript.py` 的 `--glossary` 以项目术语文件为主——行业库中的通用词（如"无人机""卫星"）几乎每句都出现，整库传入会把过多片段标为高风险。

术语库和参考文件都是核对工具，不能成为新增会议事实的来源。纪要中不写“参考 BP”“经术语核对”“转录识别为”等加工说明；核对过程保存在修订记录与复核清单中。

行业库词条可直接编辑对应文件扩充并提交仓库；新增其他行业时在 `industry/` 下新建 `<行业名>.txt` 即可。

## 自定义禁词文件（本地，可选）

`banned-phrases.txt`：机构自定义的纪要禁用表述，每行一条短语，`#` 开头为注释行。`quality_check.py` 启动时自动加载并与内置禁用表述同等拦截（同样通过 `--allow-line` 放行转录稿真实谈及的内容）。该文件与项目术语文件一样仅存本地，不随技能分发。

```text
# 示例：宣传腔与机构红线词
赋能
形成闭环
```

本目录下除本说明和 `industry/` 外的文件属于用户数据，发布或分发技能时不应包含。新版安装器默认不复制源私有数据；`--force` 更新保留目标私有数据，不删除整个技能目录。手工压缩目录不会自动遵循 `.gitignore`，应按上述边界排除。
