# Meeting Minutes Pro

完成用户交给你的整条任务：**音视频 → 原始转录 → 独立复核与证据修订 → 完整纪要 → 校验与 DOCX**。ASR 负责识别，智能体负责理解、纠错裁决和按规则写作，脚本负责可重复的处理与检查。仅完成 ASR 或生成了 DOCX，均不代表完成正式纪要验收。

## 连续完成，不增加中途确认门槛

用户调用技能要求生成纪要，且完成首次集中信息答复后，即按既定目标连续完成整条任务。证据稿修订、`accept`、`needs_authoring`、`agent_action`、review 模板均为**智能体继续工作的内部阶段**。不得在这些节点用 final 结束，不把中间稿交给用户检查后再继续，不询问“是否继续生成”，不等待用户另发“生成”指令。只有用户明确要求分阶段审阅或暂停时，才按其要求停下。

智能体自行完成能力范围内的证据核对、纪要起草、清单填写、文档生成与检查。分歧经过现有证据和可用回听仍无法确定时，只将不误导的可确认内容写入纪要；保留原始证据及未决状态，疑点、遗漏处理和能力限制随最终交付集中披露，不新增中途用户裁决门槛。不伪造实际回听、确认结论、检查成功或正式验收状态；客观执行失败时完成仍可执行的部分，并在最终交付如实说明未完成项。

## 开始执行

1. 确定输入和目标。有媒体按 audio 路径；仅有用户指定转录稿或笔记分别按 transcript / notes 路径，不补称音频回听。用户只要转录时在转录与适用复核完成后结束，尊重指定输出格式。
2. 以本次加载的 `SKILL.md` 目录为 `<skill-dir>`，脚本、输入和输出使用绝对路径。每场会议独立放入以录音文件名命名的任务目录；中间文件不得写进技能公共目录。使用运行环境检查返回的 Python 路径，避免混用系统解释器。
3. 从对话和已提供材料提取基本信息；一次性询问确实缺失的时间、地点、对象、人员、项目及热词，并询问是否有辅助文件。已有信息不重复问。等待期间先做本地环境/媒体检查、术语准备和不依赖这些答案的转录；缺少元信息不阻塞技术处理，未知字段最终省略。首次答复后直接继续，不重复索取整条流程的确认。详细采集与转录操作见 [acquisition-and-transcription.md](references/acquisition-and-transcription.md)。
4. 执行转录、复核或正式验收前读取 [evidence-and-release.md](references/evidence-and-release.md)；起草纪要前读取 [format-and-output.md](references/format-and-output.md)；进入文本检查和文档交付时读取 [minutes-and-delivery.md](references/minutes-and-delivery.md)。按阶段加载，安装说明和底层架构只在需要时读取。

## 不可丢失的业务约束

- 有录音时，录音及其经核对修订的转录稿是会议内容事实源。BP、公司介绍、尽调资料、辅助笔记仅用于热词和具体模糊片段核对，不提供纪要提纲，不补入会议未说的数字、事实或结论；其数字与段落不得进入 ASR `--context`。
- 保留每项量化事实的对象、数值或区间、单位、时间、条件、比较基准及“约、预计、不含”等限定词。先逐窗梳理事实和问答，再写完整总结；不能靠摘要压缩删掉重要数字或实质问答。
- 只要有一组明确问答，就先写覆盖整份材料的**完整总结概述**，再按主题列出**全部完整问答**；没有明确问答时按议题完整归纳，不虚构问题或答案。
- 总结直述实质内容，不写“姓名/角色/机构＋介绍、认为、表示”等转述外壳。仅在确需区分口径时使用准确的简短来源标签。无依据的判断、指导意见、责任人和期限均不写；保留意见、建议与已决定事项的状态差别。
- 纪要所有位置不写解释性括注、ASR/回听/来源材料等加工说明、说话人编号、时间戳或置信度。必要的职务、单位、条件直接写入句子，保留公文层级编号 `（一）`、`（1）`。未确认事项只进入对话和内部复核记录，正文只保留不误导的可确认内容。
- 完整执行 [写作、内容边界与固定版式](references/format-and-output.md)，其中禁词、否定对照句式、问答空行、千位分隔和字体行距规则不能因入口精简而省略。纯文本是纪要内容基准，DOCX 必须忠实渲染该版本。

## 六阶段主线

| 阶段 | 要执行的工作 | 进入下一阶段的依据 |
| --- | --- | --- |
| 1. 输入与环境 | 确认输入事实源和输出目标；检查媒体、运行时、术语；长或重要录音试转样本 | 真实存在的输入、可用运行时、适用引擎和复核范围 |
| 2. 主转录 | 中文/中英混合默认 FunASR；方言/外语等用适用的 Qwen3-ASR；保存原始 JSON/TXT/MD 与时间定位 | 完整处理的源音频和实际输出；样本、裁剪稿不能充当整段稿 |
| 3. 独立复核 | FunASR 主稿由 Qwen 复核；数字密集、初访、尽调、路演、产品/财务讲解用 `--all`；普通会议可定向复核 | 复核报告及实际覆盖范围；智能体完成可执行的分歧核对；有依据的修订另存，未决部分保留记录 |
| 4. 证据与起草 | 按窗口列量化事实及实质问答；依据确认的转录稿写完整总结和完整问答 | 原始稿保留；发生修订有 accepted 稿及 revisions；重要内容可追溯 |
| 5. 文本与 DOCX | 覆盖审计、问答对账、事实/格式检查；生成 DOCX，回读内容和样式，渲染逐页检查 | 机械检查通过，事实/警告和全文版式实际复核完成 |
| 6. 正式验收 | 用最终文件生成并填写版本绑定的 review 清单；以相同输入执行 release 检查 | `release_ready: true`；否则如实交代仍未完成的步骤和当前成果状态 |

统一执行入口是 `scripts/meeting_workflow.py`。`init` 记录输入、命名信息、配置和路径；`run` 根据产物状态推进可执行阶段。缺正文时返回 `agent_action: author_minutes`，智能体在当前任务内完成证据核对、纪要起草及覆盖清单后再次 `run`；脚本继续 draft、DOCX、render 和 review 模板。需要全文复核时返回 `agent_action: review_document`，智能体实际核对、据实填写清单后再次 `run` 完成适用 release。这些动作标记 `continuation_required: true`、`user_input_required: false`；旧 `needs_authoring` 状态同样按内部继续动作处理。`status` 查看可复用阶段与下一步，`accept` 选择有依据的修订稿并给出后续动作；登记修订稿后立即接着生成纪要，不等待用户检查。脚本不代写语义内容；智能体负责完成起草与实际复核，不能自动填造确认。完整示例见 [采集与转录](references/acquisition-and-transcription.md) 和 [纪要编写与交付](references/minutes-and-delivery.md)。

两引擎共同服务于可信转录，不能把“两个模型有输出”当作识别正确。当前自动复核器支持 **FunASR 主稿 → Qwen 复核**；Qwen 主稿再次由 Qwen 重跑不算独立双引擎。没有适用独立引擎时披露限制，不改写元数据或伪填高保障状态。高风险全量复核不得按硬件档位或时间预算静默降级；用户明确选择降低保障等级时记录理由。

实际回听指读取并理解对应音频，剪片、ASR 重跑和模型投票均不能替代。没有音频理解能力时，继续根据可确认内容完成纪要和可执行检查，保留无法裁决的片段，在最终交付集中说明；不能编造 `listened`、审阅者或确认结论，也不为此另设中途确认。

## 执行边界与交付

- 模型下载与运行在本地，不上传录音，不静默切换云端接口。首次下载、安装字体等操作遵循用户已有授权；尚未授权时说明具体变更并询问，不重复索取已给的许可。`--offline` 的边界及模型缓存排查见 [runtime.md](references/runtime.md)。
- ASR 输出默认保留 TXT、MD、JSON，真实时间戳存在时有 SRT；说话人分离仅为轮次标签，不能凭编号猜姓名。运行器、模型和设备以实际输出为准。
- 每场会议独立归档原始转录、适用的修订稿/修订记录、复核报告、覆盖清单、纪要 TXT、review、检查摘要、渲染报告及 DOCX。渲染 PDF 逐页检查后删除，用户明确索要 PDF 时保留。
- 多录音逐个完成整条流程，不混排证据和纪要；同项目复用经确认的私有术语，全部处理后在对话集中列出仍需确认的片段及放行理由。
- 最终文件名统一为“项目名称/访谈人名_会议纪要_访谈时间”：`/` 表示二选一，优先项目名称，无项目名称时用访谈对象姓名，不用我方访谈人员或记录人姓名；示例 `项目甲_会议纪要_2026-11-01.docx`。日期只用用户已确认的访谈时间，不用当前日期或文件时间代替；完整命名与缺项处理见 [输出规范](references/format-and-output.md)的“最终文件命名”。TXT、DOCX 和渲染报告保持同一文件 stem。
- 正式纪要默认交付 DOCX，附可追溯转录及实际处理状态。`checks_passed` 仅表示机械检查通过；缺模型、缺回听结论、缺字体或缺渲染条件时，不称“全部核验通过”。
