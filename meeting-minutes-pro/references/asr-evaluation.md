# 用实际录音评估转录

`scripts/evaluate_asr.py` 是标准库文本评测器，不运行 ASR、不下载音频、不代替人工回听标注。单元测试证明程序行为，合成文本验证计算方式；它们均不能证明真实会议转录准确无误。模型输出一致也可能共同出错。

## 参考集准备

先选代表实际业务的录音片段，覆盖项目专名、数字单位、否定和承诺、多人远场、口音、中英混合、静音及重叠发言。可从约 30–60 分钟总样本开始，这只是便于起步的建议，不是足以证明准确率的门槛。把词库调优材料与最终留出测试集分开，不能根据测试集答案反复调词后仍称独立验证。每个片段只对应自己的参考文本与 ASR 结果。

```powershell
<runtime-python> <skill-dir>/scripts/evaluate_asr.py init --audio <clip-001.wav> --audio <clip-002.wav> --output <job-dir>/dataset.json
```

`init` 只生成 `draft_requires_annotation`，文本为空、`annotation_status` 为 `unverified`、审阅者为空，并记录实际音频路径与 SHA-256；不会编造标签，也不覆盖已有参考集。按录音回听填入逐字参考文本，核实后填写真实审阅者并把状态改为 `human_verified`。合成或程序生成的标签必须标为 `synthetic`；没有核实的仍为 `unverified`。

参考文件为 `schema_version: 1` 与 `samples` 数组。单个样本示例：

```json
{
  "id": "sample-001",
  "audio": {"path": "clip-001.wav", "sha256": "填写实际音频的64位SHA256"},
  "text": "公司预计营收30万元，目前尚未签约。",
  "annotation_status": "unverified",
  "reviewer": "",
  "expected_terms": ["公司"],
  "critical_checks": [
    {"id": "revenue", "kind": "number", "accepted_phrases": ["30万元"]},
    {"id": "contract", "kind": "status", "accepted_phrases": ["尚未签约"]}
  ]
}
```

该段仅展示格式，不能当成真实录音标注。`audio.path` 相对路径以参考文件目录为基准；也兼容样本级 `audio` 字符串或 `path`，配合样本级 `sha256`。`expected_terms` 的每个词必须真实出现在参考文本；`critical_checks` 每项至少一个可接受短语须出现在参考文本。不可凭辅助资料数字构造“标准答案”。

## 比较结果

分别运行待比较的 ASR 配置，把片段原始识别结果导出为以下结构，不要先人工纠错再用来评价原始 ASR：

```json
{
  "schema_version": 1,
  "model_metadata": {"engine": "qwen", "model": "实际模型名称或版本", "context_manifest_sha256": "实际值"},
  "samples": [{"id": "sample-001", "text": "实际识别文本"}]
}
```

模型元数据由调用者据实填写，建议记录模型版本、设备、语言、热词清单哈希和处理参数。同一参考集对“无热词/原热词/新词表”、Qwen 0.6B/1.7B 等候选分别打分；大模型或更多热词是否改善，须以实际结果判断，不能预设胜出。使用完全相同的音频片段与标签，比较整体 CER、专名漏识别和错插、关键数字/状态，并回听典型错误。速度与资源占用另用真实运行记录比较。

```powershell
<runtime-python> <skill-dir>/scripts/evaluate_asr.py score --reference <job-dir>/dataset.json --hypothesis <job-dir>/hypothesis.json --output <job-dir>/evaluation.json
```

每个样本归一化后至多 4,000 字符，参考和识别结果都受限制；长会议应先切为带音频对应关系的小片段，避免全文编辑距离的二次方开销。重复 ID 或识别结果多出未知 ID 会报错；缺失 ID 会明确列出，并将该段参考文本计作整段删除，不能通过漏交困难片段提高指标。空的识别样本列表可用于核对全缺失情况。

## 如何解释指标

- **CER**：逐字符精确编辑距离，记录替换、删除、插入，整体按参考字符数加权。忽略空白及普通 Unicode 标点，保留数字之间的小数点、分隔符、数字前符号及数字后百分号，也保留数字和大小写；不把“三”自动归一成“3”，不让“3.5/35”“30%/30”等数字错误被去标点掩盖。重要单位和口径仍须配合原文关键检查及回听。误插很多时 CER 可大于 1，不能强行截断。参考全文为空时 CER 为 `null`，插入字符单列，不能报成 100% 正确。
- **术语**：对整份参考集 `expected_terms` 的并集，按每个样本是否字面出现计算精确率、召回率和错插词。同一词每样本计一次；这不是发音、实体身份或词义准确率，也不能检测未列入词表的任意幻觉。
- **关键检查**：只报告接受短语是否字面出现。否定或相反语境可能仍含目标短语，所以不提供“语义准确率”；例如“并非已经签约”仍包含“已经签约”，必须回听并核对实际状态。
- **证据范围**：报告记录参考集与识别结果哈希、标签状态、审阅者、模型元数据、样本明细和缺失样本。只有 `human_verified`、真实审阅者字段、音频文件存在且哈希匹配的样本才进入 `eligible_audio_only`。该检查只验证文件与声明条件，不验证审阅者身份、音频解码质量或是否实际认真回听。合成、未核实、缺音频或哈希不符的样本仍可检查计算，但不能据此宣称真实音频准确率。

保存原始识别、修订后文本与纪要为不同成果；如需评价人工/智能体修订后的质量，另生成识别结果文件并明确标注处理阶段。最终会议纪要还需核对事实覆盖、数字对象和限定条件，不能用 CER 替代纪要验收。
