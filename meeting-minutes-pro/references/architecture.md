# 排版层架构说明

本文件记录会议纪要「排版层」的分层结构，以及是否引入文档模型（IR）的架构决策与
**触发条件**，供后续维护参照。改动排版相关脚本前先读本文件与
`format-and-output.md`。

## 1. 分层

纯文本纪要是唯一真源（SSOT），DOCX 只是它的一次渲染，`check_all --docx` 的逐段
回读把「渲染必须 1:1 忠实于文本」变成硬约束。排版层内部分为：

```
规约层  format_spec.py
        └ 层级识别正则、角色→字体/字号/加粗、西文段规则、页面几何、
          首行缩进（字符单位）、字体清单——唯一真源
        └ 被 quality_check / create_minutes_docx / render_docx /
          font_preflight / embed_fonts / docx_style_check 全部 import
渲染层  create_minutes_docx.py   文本 → DOCX（角色映射·西文段·字符缩进·QA 分隔）
嵌入层  embed_fonts.py           ECMA-376 混淆嵌入 + 反混淆校验（fsType 闸门）
验收层  quality_check.py         文本层：缩进/层级/标点/问答/禁词（面向「行」）
        docx_style_check.py      样式层：逐段核验 run 字体/字号/加粗（不渲染）
        render_docx.py           渲染层：字体替换 + 页码奇右偶左（PDF 坐标）
        check_all.py             一键编排：内容回读 + 样式回读 + 副标题精确核对 + 归档
```

核心原则：**层级识别与角色字体只在 `format_spec` 定义一次**，校验器与渲染器共用，
判定不会漂移。

## 2. 决策记录（ADR）：是否引入文档模型（IR）

- **状态**：暂不引入系统级 IR（决策于 2026-07，排版层两波升级之后复评确认）。
- **背景**：IR 指把纯文本先解析为一串带类型的块（Title / Meta / Heading /
  Body / Q / A / QASep），消费者读块而非用正则读文本。曾作为「第二波」候选。

### 决策理由

1. **判定漂移已由 `format_spec` 消除**——IR 当初最大的收益（校验与渲染判定统一）
   已被规约收敛提前拿走，不再是引入 IR 的理由。
2. **校验层天生面向「行」，且应当如此**。`quality_check` 报的错是「第 X 行未以两个
   全角空格起首 / 半角标点 / 基本信息顺序」，用户按行号修改；缩进、标点、元信息
   顺序不映射到语义块。把校验器搬上 IR 只会让它变成还得回带行号的四不像。
3. **当前无 IR 消费者**。渲染目标只有 DOCX 一个；`docx_style_check`（从 DOCX 回读）
   与 `render_docx`（在 PDF 上量坐标）都不消费前向 IR。元信息专属版式、第二渲染
   目标均无现实需求。
4. **三次法则**：抽象层应等到有 2–3 个真实消费者再建。为不存在的需求先建能力层
   是过度设计。

### 触发条件（满足任一即建，且只建渲染侧）

1. 新增**第二个渲染目标**（HTML 预览 / Markdown / 另一套导出）；
2. 出现**元信息专属版式**需求（标签列对齐、加框等）；
3. 解析逻辑出现**第三个前向消费者**。

### 若建，约束

- **只建渲染侧**：在 `create_minutes_docx` 内抽 `parse_blocks(lines) -> [Block]`，
  渲染器读块；顺带清掉 `pending_blank` 状态标志与「元信息当正文」两处 smell。
- **绝不把 `quality_check` 搬上 IR**——它面向行是正确的设计，保持不变。
- 块类型仍从 `format_spec` 取角色/字体定义，`format_spec` 保持唯一真源。

### 未采纳的替代

- *现在就做渲染侧小型块模型*：可行且低风险，但收益基本是 future-proofing，
  当前无第二消费者，按三次法则暂缓，留作上述触发条件命中时的第一步。
